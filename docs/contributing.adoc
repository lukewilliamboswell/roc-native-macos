= Contributing

This chapter is for people changing the platform: building it, bundling it,
driving its examples and passing the check gate. The repository's rules are
in `AGENTS.md`; xref:architecture.adoc#how-it-fits-together[Architecture]
explains the design.

[#build-the-platform]
== Build the platform

Building the platform itself (not an app: an app needs only Roc, on any
system) needs Apple silicon macOS, Xcode's `swiftc`, `python3`, and a Roc compiler
installed as `roc`: a current nightly, or 0.1.0 RC1. The repository follows
https://github.com/lukewilliamboswell/roc-automation[roc-automation], and
https://github.com/lukewilliamboswell/roc-blueprint[Blueprint] 0.13.0
provides the rest of the environment.

[source,sh]
----
scripts/build.sh                # glue, Swift host, linker stubs, every example
scripts/build.sh counter        # one example, after the platform is built
scripts/build.sh --platform     # only the platform's native inputs
./examples/counter/counter      # or stopwatch, todos, http-fetch, file-inspector, gallery, contacts
open examples/counter/counter.app
----

`scripts/build.sh` uses the 0.1.0 RC1 compiler at
`~/roc-macos_apple_silicon-0.1.0_RC1/roc` unless `ROC=` names another; the
Blueprint tasks pass `ROC=roc`. Building the platform is three steps:

. *Glue.* `roc glue glue/SwiftGlue.roc` writes `host/roc_swift_abi.h` and
  `host/RocGlue.swift` (see xref:architecture.adoc#glue[Glue]).
. *Host.* `swiftc` builds `host/*.swift` into
  `platform/targets/arm64mac/libhost.a`, with framework autolinking and
  `FORCE_LOAD` symbols off.
. *Linker stubs.* `scripts/build_macos_stubs.py` writes
  `platform/targets/macos-sysroot` from `host/interfaces.json` and audits
  `libhost.a` against it (see
  xref:architecture.adoc#linker-inputs[Linker inputs]).

None of these outputs is committed.

CI and releases build the host with Xcode 26.3 (Swift 6.2.4), selected by
`.github/actions/setup-xcode`. The Swift version decides which Swift runtime
symbols `libhost.a` references, and so what the stub audit accepts: Xcode
16.4's Swift 6.1, the runner image's default, references four that Swift 6.2
inlines. To move to another Xcode, change the action's two defaults, run the
check gate with that Xcode, and catalog any symbol the audit names.

Each example is built twice over: the bare binary, and a minimal `.app`
bundle beside it (`Contents/MacOS/<name>` and an `Info.plist` with
`CFBundleIdentifier` `dev.roc.native.<name>` and `LSMinimumSystemVersion`
11.0, the `minos` Roc's linker writes). Launched from the bundle, AppKit has a
bundle identifier, so it no longer warns that it cannot index window tabs.
The two keep separate `UserDefaults` domains (`todos` versus
`dev.roc.native.todos`), so they do not share saved values.

=== Blueprint tasks

[cols="2,3",options="header"]
|===
| Task | Does

| `blueprint run check` | the pull-request gate; `check -- STAGE...` runs the named stages
| `blueprint run build` | `scripts/build.sh`: glue, host, stubs and every example; `build -- counter` for one
| `blueprint run test` | `roc test` on the platform root and every example
| `blueprint run examples` | every example's recorded scripted runs; `examples -- --update` records new output
| `blueprint run bundle` | the platform bundle, in `build/platform/` (see xref:contributing.adoc#the-bundle[The bundle])
| `blueprint run release` | the release steps after the bundle: `tool`, `archive`, `test` and `notes` (see xref:contributing.adoc#releasing[Releasing])
| `blueprint run tooling-version` | the scripts' compiler version
|===

=== Two compilers

`roc`, the latest Roc nightly, checks, builds and tests the platform, the
glue, the examples and the `macos.roc` tool (`cli/`). It is never pinned: CI
installs the nightly of the day, and a contributor installs a current nightly
(or RC1) as `roc`.
`roc-stable`, which `Blueprint.roc` pins to `nightly-2026-11-14-a87808d`,
runs the scripts under `scripts/`, and only those scripts name it in their
headers (`roc: "<tag>"`). Format the scripts with `roc-stable fmt`.

[#the-bundle]
== The bundle

App authors name the platform by the URL of a bundle:
`app [main] { pf: platform "https://…/<hash>.tar.zst" }`. `blueprint run
bundle` (`scripts/bundle.roc`) makes that bundle:

. It builds the platform's native inputs (`scripts/build.sh --platform`),
  unless `--prebuilt` is given.
. It stages, under `build/bundle-stage/`, the tracked `platform/*.roc`
  modules, `targets/arm64mac/libhost.a`, the generated
  `targets/macos-sysroot/` stubs, `LICENSE` and `THIRD_PARTY_LICENSES.md`.
  The stubs are the catalog's generated TAPI files, not Apple SDK files.
. It runs `roc bundle` there with `main.roc` first, which writes one
  content-addressed `<hash>.tar.zst` to `build/platform/` (or
  `--output-dir DIR`), and prints its size and SHA-256.

`blueprint run bundle -- --test` then checks the bundle the way an author
uses it. It copies the bundle to `build/bundle-test/served/` and serves that
on localhost (Roc accepts `http` URLs for localhost only), makes the
`macos.roc` tool there naming the served URLs (`release -- tool`, see
xref:contributing.adoc#the-tool[The tool]), and with an empty package cache
(`XDG_CACHE_HOME`) runs `roc macos.roc init counter`, then `roc macos.roc
build` and `roc macos.roc test` in `build/bundle-test/counter/`, which runs
the counter's recorded cases. The `bundle` stage of `check` does the same with
`--prebuilt`. The empty cache means basic-cli and the platform's own
dependency (roc-parser) are downloaded from GitHub on every run.

To build an app outside the checkout against a local bundle, serve
`build/platform` and name the localhost URL in the app's header. The bundle's
name is its content hash, so the URL changes whenever the bundle does. An app can also name a checkout's platform by a relative
path, `platform "../roc-native-macos/platform/main.roc"`, once
`scripts/build.sh --platform` has built its native inputs; Roc rejects an
absolute platform path.

A release publishes the bundle under
`releases/download/<version>/<hash>.tar.zst`; see
xref:contributing.adoc#releasing[Releasing].

[#the-tool]
== The tool

`macos.roc` is the app author's tool: `init`, `build`, `run` and `test`. It
is a package, `cli/`, on basic-cli, which a release bundles and names from a
small launcher app, `macos.roc`, that the author downloads (the same model as
roc-native-android's `android.roc` and roc-signals' `signals.roc`):

[cols="1,3",options="header"]
|===
| Module | Does

| `cli/main.roc` | the package root, exposing `MacOS`
| `cli/MacOS.roc` | the command line: parsing, `help` and `COMMAND --help`, and every failure put into one sentence (`explain`; exit code 2 for misuse)
| `cli/Init.roc` | `init`: the counter scaffold, never overwriting a file
| `cli/App.roc` | `build` and `run`: `roc build --target=arm64mac` into `.macos/<name>`, then `<name>.app` with its `Info.plist`
| `cli/Cases.roc` | `test`: each `tests/<case>.script` run with `ROC_SCRIPT` against `.macos/<name>`
| `cli/Recorded.roc` | the recorded-case rules (`matches`, `portable`), shared with the scripts
| `cli/Bundle.roc` | generated: the release, its platform URL, the Roc that tested it, and the scaffold
|===

`build` writes files and runs `roc`, nothing else, so it works on any system:
Roc's linker signs the program ad hoc (`codesign -dv` shows
`adhoc,linker-signed`), and the `.app` is a directory and a plist. It always
passes `--target=arm64mac`, which on an Apple silicon Mac is the native
target. `run` and `test` need an Apple silicon Mac, and say so elsewhere.

`cli/Bundle.roc` is generated by `scripts/src/Release.roc`. The checked-in
copy is for a checkout: version `development`, importing the scaffold
(`examples/counter/main.roc` and `tests/examples/counter/*`) from the working
tree, so `roc test cli/main.roc` works. A release generates its own, importing
copies staged under `scaffold/`. The `tool` stage of `check` fails when the
checked-in copy is not what the script generates (when a counter case is
added, say); `blueprint run check -- tool --update` rewrites it.

A script cannot import a module outside `scripts/`, so
`scripts/src/Recorded.roc` is a byte-identical copy of `cli/Recorded.roc`,
which the `tool` stage checks. Change `cli/Recorded.roc`, then copy it over.

`blueprint run release -- tool VERSION DIR` makes the tool for the platform
bundle in `DIR`: it stages `cli/` with the release's `Bundle.roc`, the
scaffold and the notices under `build/tool-stage/`, runs its `expect`s,
`roc bundle`s it into `DIR/macos-<hash>.tar.zst` (the prefix keeps it apart
from the platform's bundle), and writes `DIR/macos.roc` naming it.
`--base-url URL` names the assets at `URL` instead of the release's download
URL, to try a release locally:

[source,sh]
----
blueprint run bundle -- --prebuilt --output-dir /tmp/rel
python3 -m http.server 8787 --bind :: --directory /tmp/rel &
blueprint run release -- tool 0.0.1-dryrun /tmp/rel --base-url http://localhost:8787
cd "$(mktemp -d)" && curl -LO http://localhost:8787/macos.roc
roc macos.roc init counter && cd counter && roc macos.roc run
----

[#driving-an-app]
== Driving an app

`ROC_SCRIPT` drives the real controls through the same action methods AppKit
calls. Steps run every 100 ms; `dump` prints the live view tree:

[source,sh]
----
ROC_SCRIPT="type:Buy milk;enter;toggle:Buy milk;choose:Done;dump;quit" ./examples/todos/todos
ROC_TRACE=1 ROC_SCRIPT="type:https://example.com;enter;wait:3000;dump;quit" ./examples/http-fetch/http-fetch
ROC_SAVE_DIR=/tmp ROC_SCRIPT="files:$PWD/README.md;click:Inspect;wait:300;dump;click:Save Copy…;wait:200;quit" \
  ./examples/file-inspector/file-inspector
----

[cols="1,3",options="header"]
|===
| Step | Does

| `click:<title>` | clicks the button with that title
| `type:<text>` | types into the first text field
| `write:<text>` | writes into the first text area; `\n` is a line break
| `enter` | submits the text field's form
| `toggle:<title>` | toggles the checkbox with that title
| `choose:<title>` | chooses a dropdown item or a segment
| `select:<text>` | selects the list row holding that text
| `key:cmd+shift+n` | presses a key, delivered as if nothing had focus
| `files:<path>,<path>…` | gives files as if picked on the first file button or drop zone, with no panel
| `drop:<path>,…` | gives files as if dropped on the first drop zone
| `wait:<ms>` | waits
| `dump` | prints the window size, then the view tree; a list shows its visible rows, and a text, box or drop zone the look attributes that differ from the usual (`{color=secondary-label text-style=caption1}`)
| `window` | prints `window <number>`, for `screencapture -l<number>`
| `quit` | quits, through the same teardown as quitting
|===

[cols="1,3",options="header"]
|===
| Variable | Effect

| `ROC_TRACE=1` | logs effect requests, cancellations, minted and released file handles, the teardown (`DROP`), and each turn's engine and host time
| `ROC_POISON=1` | fills every new allocation with `Z`, to expose reads of uninitialised memory
| `ROC_SAVE_DIR` | where a scripted save writes; without it a scripted save is skipped
| `ROC_MAX_FILE_BYTES` | lowers the host's file ceiling, to check `TooLarge`
| `ROC_STORAGE_SUITE=<name>` | a `UserDefaults` suite for local storage; otherwise a scripted run's local storage is in memory
| `ROC_APPEARANCE=dark` (or `light`) | draws the app in that appearance whatever the system's, to check both looks
|===

A scripted run never takes keyboard focus, never opens a panel and never
shows the crash alert.

=== Recorded cases

Every example has at least one recorded case:
`tests/examples/<example>/<case>.script` holds the steps and
`<case>.expected` what the run prints (the `dump` trees, with the checkout's
path written `<repo>`). `blueprint run examples` runs each case against the
built app with a 60-second deadline; it must exit 0 and print exactly the
recorded output. A new example needs a case: add the `.script`, run
`blueprint run examples -- --update`, and review the `.expected` diff before
committing it. The stopwatch cases avoid wall-clock readouts.

roc-signals' `.scm` spec runner is not ported. Its oracle (`Dom.roc`) models a
browser DOM, so it would check the engine but never the AppKit host. A spec
format over the scripted driver, or a `ui-*` oracle, are the two options.

== The check gate

`blueprint run check` (`scripts/check_all.roc`) is the pull-request gate, the
same one CI runs on `macos-15`. Its stages, in order:

[cols="1,3",options="header"]
|===
| Stage | Checks

| `pins` | only the scripts pin a compiler, and they pin `roc-stable`
| `engine` | the engine modules are roc-signals' plus the patch series: `patches/roc-signals/README.adoc` lists every `*.patch` there, in order, and reverse-applying them to copies of the modules gives back the digests `tests/engine-modules.sha256` records (xref:contributing.adoc#engine-patches[Engine patches])
| `fmt` | `roc fmt --check` over the platform, glue, examples and tool (the not-yet-formatted files are skipped, and each skip prints), and `roc-stable fmt --check` over the scripts
| `scripts` | the scripts' `expect` tests
| `tool` | `cli/Bundle.roc` is current (`tool --update` writes it), `scripts/src/Recorded.roc` copies `cli/Recorded.roc`, and `roc test cli/main.roc`
| `build` | `scripts/build.sh` with the `roc` on PATH
| `test` | `roc test` on `platform/main.roc` and every example
| `examples` | every recorded case
| `bundle` | the bundle from the `build` stage's inputs, and its consumer test: `macos.roc` `init`, `build` and `test` against it
|===

`check -- STAGE...` runs only the named stages.

[#engine-patches]
== Engine patches

The engine modules are roc-signals' at the revision
xref:architecture.adoc#engine-revision[Engine] names, plus the patches in
`patches/roc-signals/`. Its `README.adoc` is the series, one line per patch
with its upstream status, and says how to make a patch. Each patch carries
a header: what it changes, why, what it measured before and after, and
`Upstream: not yet sent` or the pull request's link. When a patch lands
upstream and a newer engine is taken, the patch is dropped.

A cost that turns out to be the compiler's is not patched here. It gets a
standalone reproducer and a write-up in `patches/roc-compiler/`, listed in
its `README.adoc` for reporting to roc-lang/roc; an engine patch that only
works around it says so in its header.

[#releasing]
== Releasing

`.github/workflows/release.yml` builds what a release contains once, tests
those exact bytes, and publishes them once, as roc-automation's platform
release workflow prescribes. A maintainer dispatches it from `main` with a
version such as `0.0.1` or `0.1.0-rc1`; the tag it creates is the bare
version, with no `v`. A pull request that touches the platform, the host, the
examples, the scripts, the notes or the workflow runs it as a dry run under
`0.0.1-dryrun`, which publishes nothing.

[cols="1,3",options="header"]
|===
| Job | Does

| Validate | resolves the Roc nightly for the whole run, and refuses a version that is not SemVer, a dispatch off `main`, an existing tag, or a missing `docs/releases/<version>.adoc`
| Build (`macos-15`) | selects the pinned Xcode, runs `blueprint run check` (the whole gate, which builds the host and runs every recorded case against it), bundles that same `libhost.a` (`bundle -- --prebuilt`), makes the `macos.roc` tool naming it (`release -- tool`), writes the examples archive (`release -- archive`), builds every archived example against the bundle served on localhost with an empty package cache and runs every recorded case, then with the served `macos.roc` creates, builds and tests a counter (`release -- test`), binds the bundle's SBOM sidecars (`actions/sbom-sidecars`, from `sbom/composition.json`) and renders the notes (`release -- notes`)
| Cross-compile (`ubuntu-24.04`, `ubuntu-24.04-arm`, `windows-2025`) | with only Roc installed and no checkout, serves the candidate on localhost, builds every archived example with `--target=arm64mac`, and with `macos.roc` creates a counter and builds `counter.app`; each program must be an arm64 Mach-O executable. It also records what `roc build` without `--target` does there.
| Run the cross-compiled apps (`macos-15`) | runs every recorded case against each system's cross-compiled apps and the counter's against its `counter.app` (`release -- test DIR --binaries BIN`)
| Attest | build-provenance attestations for every file, an SBOM attestation for the bundle, exported as `<file>.intoto.jsonl`
| Publish (`release` environment) | checks out nothing and runs no repository code: `actions/publish-release` stages a draft at the tested commit, downloads every asset back and compares it with the tested file, then publishes
|===

A release holds the bundle `<hash>.tar.zst`, its SBOM documents
(`.spdx.json`, `.spdx-2.3.json`, `.cdx.json`, `.sbom-manifest.json`),
`macos.roc` and the tool's package `macos-<hash>.tar.zst`,
`roc-native-macos-examples-<version>.zip` (every example naming the release
URL, with its recorded cases and fixtures), and the exported attestations. The
notes are `docs/releases/<version>.adoc` with `{platform-url}`,
`{examples-url}` and `{launcher-url}` (`macos.roc`) filled in, followed by
the compilers, the Xcode and Swift versions, and every file's SHA-256.

The bundle's hash depends on `libhost.a`, which is not byte-reproducible, so
the URL is known only once the build job has run. It is printed at the top of
that job's summary, in the notes, and in the dry run's summary.

To cut a release:

. Write `docs/releases/<version>.adoc`, opening with
  `= roc-native-macos <version>` and naming the platform as
  `{platform-url}`, and merge it. The pull request's dry run renders it.
. Run *Release* from the Actions tab on `main` with the version, or
  `gh workflow run release.yml --ref main -f version=<version>`.
. Approve the `release` environment's deployment when the tests pass.
. If publishing stops partway, follow roc-automation's "Recover an
  interrupted publication": delete a draft and re-run the publish job; a
  published release is never repaired.

The repository needs a `release` environment limited to `main` (with a
required reviewer if wanted), immutable releases enabled, and Actions allowed
to create attestations (the attest job asks for `id-token: write` and
`attestations: write`). No secret is needed: every job uses the workflow's own
token.

The scripts the workflow runs are tasks, so the build job's steps run the same
way locally (with the nightly as `roc`):

[source,sh]
----
blueprint run check
blueprint run bundle -- --prebuilt --output-dir build/release
blueprint run release -- tool 0.0.1-dryrun build/release
blueprint run release -- archive 0.0.1-dryrun build/release
blueprint run release -- test build/release
blueprint run release -- notes 0.0.1-dryrun build/release build/release-notes.md
----

[#styling]
== Styling

Apps style elements through props records in AppKit's own vocabulary; the
API is in xref:ui.adoc#ui-looks[the Ui reference] and the attribute grammar and
AppKit mapping in xref:architecture.adoc#looks[Looks]. Adding a look:

. a defaulted field on the props type in `Ui.roc` whose type is a tag union
  (or a number with a real native default), with a "platform decides" tag
  such as `Auto` or `Standard` rather than a magic zero;
. a word function outside the `Ui := [].{ … }` block, and an `expect` for
  its words;
. an `applyAttr` case in `host/Views.swift` that parses the word and calls
  `fatal` on anything else, independent of the order attributes arrive in
  (a template row applies them in dictionary order);
. any new AppKit symbol in `host/interfaces.json`, by documented ownership;
  watch for Swift type metadata (a stored `NSEdgeInsets` or `[CGFloat]`
  names CGFloat's descriptor in `libswiftCoreGraphics`, which the stubs do
  not link);
. a row in `docs/ui.adoc` and `docs/architecture.adoc`.

Check both appearances with `ROC_APPEARANCE=dark` and a screenshot
(`window`, then `screencapture -l<number> -o`).

[#findings]
== Findings

List capacity encoding:: In `capacity_or_alloc_ptr` a list stores
`capacity << 1`; the low bit marks a seamless slice. The first host stored
the raw length, so any odd-length payload read as a slice with a bogus
allocation pointer and crashed in `roc_llvm_rc_decref`. Two-byte clicks
passed by luck. The Zig glue gets this right; the C glue offers no
constructor, hence SwiftGlue, which now replaces the C glue entirely.
Single-field record builder:: `{ a: Engine.cell(…) }.Engine.Cells` with one
field is unimplemented in RC1, but `roc build` compiles it to a runtime error
instead of failing. `roc test` reports it.
`watch` vs `watch_latest`:: `watch` never cancels what it issued; a
start/stop interval needs `watch_latest`.
Handles in host memory work as in Wasm:: RC1's native code frees a
`Box(U64)` at its payload minus 8 with alignment 8, exactly where the glue
facts put it, so a box minted in a host table (not from `roc_alloc`) is
released through `roc_dealloc` like the browser host's blob heap, and the
same token encoding carries over unchanged. A list of such boxes must be
built with the 16-byte header (element count, then refcount), which Roc reads
when it releases a seamless slice of the list. A host that wrote the 8-byte
header of a byte list would work until such a slice was released.
Props records work:: A nominal record of `??` defaulted fields as a function
argument (`Ui.vstack({ align: Fill }, kids)`, `Ui.scroll({}, rows)`) checks,
builds and runs correctly in RC1, for every field type `Ui` uses: tag unions,
nested and nominal records (`padding: Each({ top: 4 })`), functions,
handlers and signals (`enabled : Signal(ctx, Bool) ?? Engine.const(Bool.True)`).
`{}` takes every default, and partial literals take them inside a `map`
lambda and through `Engine.const` too.
An unannotated props value takes no defaults:: `card = { padding: All(4) }`
is inferred as its own closed record, so passing it where `Ui.BoxProps` is
expected fails to type-check ("missing these fields"), and `{ ..card,
radius: 4 }` says the field does not exist. Annotated (`card : Ui.BoxProps`)
it works. Themes are annotated for this reason.
Props error messages (compiler, not reported upstream):: A misspelt field
(`{ spaceing: 12 }`) gets a type mismatch whose found type lists the
misspelling beside the real fields, with no "did you mean" hint, though a
misspelt tag gets one ("Maybe Centre should be Center?"). A literal missing
a required field gets `Hint: This record is missing these fields`, which
wrongly lists the defaulted fields it also omits.
A text literal is a constant signal:: `Signal` has `from_quote` and
`from_interpolation`, so `Ui.text("Hi", {})` and `Ui.text("${count} left", {})`
need no `Engine.const`, but a `Str` held in a name does.
Attributes arrive in any order:: A template row's views are made and then
given every attribute from a dictionary, so a host handler must not depend
on another attribute having been applied first. `title-display` (an
`NSButton`'s `imagePosition`) is reapplied after any title, bezel or size
change for this reason; before that, icon-only buttons in rows drew their
titles over their symbols.
No `Str` order:: `Str` has no `order_relative_to` in RC1, so `Engine.sort_by`
cannot sort rows by a name; `contacts` sorts by key.
Host costs, not engine costs:: For 10k rows the engine's turns are
milliseconds; the host was seconds until it stopped removing children one
O(n) scan at a time (removals now compact once per batch) and stopped
creating AppKit views for list rows nobody had scrolled to.
A bundle is fetched only over https, or http to localhost:: RC1 rejects a
local `.tar.zst` path as a platform ("that package does not have a platform
header") and any `http` URL that is not localhost. A server listening on
`127.0.0.1` alone was not reached for `http://localhost:…`; one listening on
`::` was, so serve the bundle with `--bind ::`. RC1 also rejects an
absolute platform path. Current compilers (`src/unbundle/download.zig`)
accept plain `http` for the hosts `localhost`, `127.0.0.1` and `[::1]`, and
connect to `localhost` on the first loopback address it resolves to, which
is `::1` on macOS; a dual-stack server on `::` serves both.
The same inputs bundle to the same name, but a rebuilt host does not:: Two
builds of `libhost.a` from the same sources are not byte-identical, so
`scripts/build.sh --platform` gives the bundle a new content hash each time.
Bundling the same built inputs again (`--prebuilt`) gives the same hash.

== Reporting

Report vulnerabilities as `SECURITY.md` describes. What the repository adopts
from roc-automation so far, and what is left, is in
xref:roc-automation-review.adoc#summary[the roc-automation review].
