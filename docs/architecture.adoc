= Architecture

This chapter is for contributors. It explains how an app, the engine and the
Swift host fit together, what crosses between them, and the rules the host
follows for effects, threads, files, the ABI and linking. App authors need
none of it; xref:ui.adoc#builders[the Ui reference] is theirs.

== How it fits together

[mermaid]
....
flowchart TB
    App["app (Roc)"] -- "Ui / Engine" --> Engine["engine: roc-signals package, pure Roc"]
    Engine -- "command stream (roc-signals wire protocol 23)" --> Host["Swift host: host/Host.swift"]
    Host --> Views["AppKit views"]
    Host -- "AppKit events, effect results: one engine turn each" --> Engine
....

Engine:: roc-signals 0.8.0-rc2's standalone engine package, which
`platform/main.roc` names as `engine`. `platform/Engine.roc`, `Layout.roc`,
`Wire.roc` and `Worker.roc` are generated facades that re-expose the
package's modules of the same names, since a platform cannot expose a
package's module itself (xref:contributing.adoc#engine-package[The engine
package]). The worker layer's platform side, `Files`, `Hosted` and
`Effects`, is this platform's: it binds the job effects to the
`roc_task_*` hosted functions.

Platform root:: `platform/main.roc` is a trimmed copy of roc-signals' root,
built on the package's `EngineHost`.
It provides `roc_engine_keys`, `roc_engine_init`, `roc_engine_event`,
`roc_engine_files` (a files-kind event, copied as is), `roc_engine_drop` and
`roc_engine_version` for the page's instance, and `roc_engine_work`,
`roc_engine_prepare`, `roc_engine_ask` and `roc_engine_forget` for worker
instances (xref:architecture.adoc#workers[Workers]), with the `roc_task_*`
hosted functions a job calls. It has no ports or crypto.
`roc_engine_keys` returns the engine's declarations without roc-signals'
section 12 (protocol facts): that CBOR item needs the cbor package and
`ProtocolFacts`, and this host binds no roles from it.

`Ui.roc`:: The native vocabulary apps use. Each builder is a plain
`Engine.element` with a native element name (`ui-vstack`, `ui-button`,
`ui-text-field`, `ui-checkbox`, `ui-slider`, …). A control's state crosses as
plain attributes (`value`, `checked`, `enabled`), and its look as one
attribute per prop (xref:architecture.adoc#looks[Looks]); the engine only
allows its `value`/`checked` _props_ on HTML inputs.

Swift host (`host/`):: Decodes the subset of the command stream the
vocabulary produces:
+
* element, text and comment creation; attributes; listeners; text updates;
* move, remove and clear;
* row templates (`TEMPLATE`/`INST`) and their holes;
* `FX` timers and intervals, and `CANCEL`;
* `FX` HTTP (kind 1) through `URLSession`, with timeouts, cancellation and
  transfer progress (see xref:architecture.adoc#effects-and-threads[Effects and threads]);
* local storage, via `UserDefaults`, and session storage, in memory for the
  life of the process;
* files: handles, reads (`FX` 11), digests (13), URLs (14) and `SAVE` (see
  xref:architecture.adoc#files[Files]).
+
It keeps a node tree mirroring what the engine built and gives each `ui-*`
element one AppKit view (`ui-hover` lends its place to its child's). It routes AppKit actions back as turns: `click`,
`input`, `change`, `submit`, a list row's `select`, a windowed list's `window` (text `start count`), key events, `hover` (text `enter` or `leave`), and the
files-kind `change` and `drop`. Any other command or effect is a clear fatal
error, not a silent skip.

A control's state crosses as attributes (`value`, `checked`, `title`,
`enabled`), because the engine only allows its `value`/`checked` _props_ on
HTML inputs. A `dropdown`'s `choices` cross as one attribute, joined by
newlines.

[#looks]
=== Looks

Every prop is one attribute, and `Ui.roc` sends every one, defaults
included, so a default lives only in Roc. A static props record goes through
`Engine.const`, and the engine sends a constant signal as a plain static
attribute; an `_s` builder's attributes follow its props signal, and the
engine writes one only when its text changes. The words come from one pure
function per type in `Ui.roc`, each with `expect`s. The host parses each
value into its AppKit setting; a word outside the grammar is a fatal error.

`width`, `height` (every element)::
`auto`, `fill`, `fill-at-least:N`, `fixed:N`, `at-least:N`, `at-most:N`, `between:MIN:MAX`. AppKit: host-owned constraints (`==`, `>=`, `<=`, required); `fill` sets content hugging to 1 on that side, and across a stack pins the side to the stack's, inside its padding.

`squeeze` (every element)::
`standard`, `yield`, `resist`. AppKit: horizontal compression resistance: the view's own, 250 or 999.

`spacing`::
`N`. AppKit: `NSStackView.spacing`.

`padding`::
`TOP LEADING BOTTOM TRAILING`. AppKit: `NSStackView.edgeInsets`; a surface's child insets.

`align` (vertical stack, form)::
`leading`, `center`, `trailing`, `fill`. AppKit: `NSStackView.alignment` `.leading`, `.centerX`, `.trailing`; `fill` pins every child's width.

`align` (horizontal stack, row)::
`top`, `center`, `bottom`, `first-baseline`, `fill`. AppKit: `.top`, `.centerY`, `.bottom`, `.firstBaseline`; `fill` pins every child's height.

`distribution`::
`gravity`, `fill`, `fill-equally`, `fill-proportionally`, `equal-spacing`, `equal-centering`. AppKit: `NSStackView.distribution`; `gravity` is `.gravityAreas` unless the stack must fill (below).

`text-style`::
`large-title`, `title1` … `title3`, `headline`, `subheadline`, `body`, `callout`, `footnote`, `caption1`, `caption2`. AppKit: `NSFont.preferredFont(forTextStyle:)`; on a symbol, `NSImage.SymbolConfiguration(textStyle:scale:)`.

`font-size`::
`standard`, `N`. AppKit: the style's point size, or `N`.

`weight`::
`standard`, `light`, `regular`, `medium`, `semibold`, `bold`, `heavy`. AppKit: `standard` keeps the style's font; otherwise `NSFont.systemFont(ofSize:weight:)`.

`design`::
`proportional`, `monospaced-digits`, `monospaced`. AppKit: `monospacedDigitSystemFont(ofSize:weight:)`, `monospacedSystemFont(ofSize:weight:)`.

`overflow`::
`clip`, `truncate-head`, `truncate-middle`, `truncate-tail`, `wrap`, `wrap:N`. AppKit: `lineBreakMode` and `maximumNumberOfLines`; a wrapping `Label` has no intrinsic width and sets `preferredMaxLayoutWidth` to the width it is given.

`text-align`::
`natural`, `leading`, `center`, `trailing`, `justified`. AppKit: `NSTextField.alignment`.

`color`, `fill`::
`label`, `secondary-label`, … `clear`, or `adaptive:RRGGBB:RRGGBB`. AppKit: `NSColor.labelColor`, `.secondaryLabelColor`, `.controlAccentColor`, `.systemRed`, …; `adaptive` is `NSColor(name:dynamicProvider:)` choosing between two sRGB colours by `bestMatch(from: [.aqua, .darkAqua])`.

`border`::
`none`, `line:W:COLOUR`, `dashed:W:COLOUR`. AppKit: stroked by the surface.

`radius`::
`N`. AppKit: the surface's corner radius.

`bezel` (button)::
`push`, `flexible-push`, `toolbar`, `accessory-bar`, `badge`, `circular`, `small-square`, `borderless`. AppKit: `NSButton.bezelStyle`; `borderless` is `isBordered = false`.

`bezel` (text field)::
`square`, `rounded`. AppKit: `NSTextField.bezelStyle`.

`role`::
`normal`, `default`, `cancel`, `destructive`. AppKit: `keyEquivalent` Return or Escape; `hasDestructiveAction`.

`icon`::
`none`, `symbol:NAME`. AppKit: `NSButton.image`, an SF Symbol.

`title-display`::
`visible`, `hidden`. AppKit: `imagePosition` (`.imageOnly` hides the title, which still names the control to VoiceOver); reapplied after a title, bezel or size change, since attributes arrive in any order.

`size`::
`mini`, `small`, `regular`, `large`. AppKit: `NSControl.controlSize`, with the font `NSFont.systemFontSize(for:)`.

`enabled`::
`true`, `false`. AppKit: `NSControl.isEnabled`.

`scale` (symbol)::
`small`, `medium`, `large`. AppKit: `NSImage.SymbolScale`.

`asset` (asset image)::
a path inside `assets/`. AppKit: `NSImage(contentsOfFile:)` of the file `Assets.path` resolves, cached by name; see xref:architecture.adoc#assets[Assets].

`scaling` (asset image)::
`fit`, `fill`, `stretch`, `original`. AppKit: the rectangle `Picture.draw(_:)` draws the image in, clipped to its bounds.

`label` (asset image)::
text. AppKit: `setAccessibilityLabel`; empty leaves the view out of the accessibility tree (`setAccessibilityElement(false)`).

`opening-height` (scroll, list)::
`N`. AppKit: a height preference (priority 300) until the window has been sized for it, then 49.

`window-start` (list)::
`N`, set by `Ui.table_list` from its window: the list is windowed, and its element children are the table's rows from row `N`. AppKit: the table row of the first child; see xref:architecture.adoc#lists[Lists].

`view-rows` (list)::
`N`, set by the engine's `table_view_counted` (patch 0006) on its parent: how many rows the view keeps. AppKit: the table's `numberOfRows` for a windowed list.

A surface (`Surface`, for `ui-box` and `ui-drop-zone`) draws its fill and
border in `draw(_:)` with `NSColor`s, where AppKit has set the view's
appearance, so a semantic or adaptive colour follows light and dark mode
without the host doing anything. A layer's `CGColor` would not.

Stack distribution:: A stack whose `distribution` is `gravity` uses `.fill`
when it has a child that fills along it (a spacer, or a `fill` width in a
horizontal stack and height in a vertical one), or, if vertical, holds a
scroll area or list; otherwise `.gravityAreas`. The child that fills hugs
least, so it takes the slack. Spacers in one stack are constrained equal, so
two of them centre what lies between.

Window sizing:: The window fits its content, measured after two layout
passes (the first gives wrapping labels their widths). Once it holds a scroll
area or list it grows only when its content needs more room.

`ROC_APPEARANCE=dark` (or `light`) draws the app in that appearance whatever
the system's, to check both looks.

[#assets]
== Assets

An app's assets are the files of `assets/` beside its `main.roc`
(xref:apps.adoc#assets[Assets and the icon]). They are delivered as files,
not compiled into the program: `macos.roc build` copies the directory into
`<name>.app/Contents/Resources/assets/` and to `.macos/assets/` beside the
program `test` runs, and `scripts/build.roc` copies a repository example's
into its `.app` (the bare `examples/<name>/<name>` finds `assets/` beside
it). Copying files works from any system, keeps images out of the binary and
out of the engine's attribute strings, and is how AppKit loads images anyway.
Data an app reads as values is better compiled in with Roc's
`import "file" as x : Str`, which needs no host support.

Lookup (`Assets`, `host/Assets.swift`):: The directory is decided once:
`ROC_ASSETS` if set (the release tests run bare programs away from their
examples), else `Contents/Resources/assets` when the program (`Bundle.main.executablePath`,
resolved with `realpath`) is in `<x>.app/Contents/MacOS`, else `assets/`
beside the program. A name with an empty, `.` or `..` component, a missing
directory or file, and a file `NSImage` cannot read are each a fatal error
naming the asset and where the host looked. Images are read synchronously on
the main thread when first shown and kept by name for the process's life.
`Picture`:: Its intrinsic size is the image's size in points, hugged and
resisted at 750; a width-to-height constraint at the image's ratio, priority
760, makes a frame bound on one side follow the aspect ratio. It draws in
`draw(_:)`, so `fill` can crop, which `NSImageView`'s scalings cannot. A
dump prints the name, the first representation's pixel size (a PDF's is its
size in points) and the frame.
The icon:: `CFBundleIconFile` names `Contents/Resources/AppIcon.icns`.
`cli/Icon.roc` makes it from a square PNG with no Apple tool: an `.icns` is
`icns`, a big-endian length, then entries of an OSType, a length and data,
and since macOS 10.7 an entry (`ic10` for 1024 pixels, `ic09` 512, …,
`icp4` 16) may hold a PNG as it is. One entry is enough: macOS scales it,
and `iconutil` writes the same layout for a one-image set. `scripts/build.roc`
only copies an `assets/icon.icns`.
Signing:: Roc's linker signs the program ad hoc; nothing seals the bundle's
resources (`_CodeSignature/CodeResources`), as before. Gatekeeper's
quarantine applies to a downloaded `.app` whatever it holds.

[#layout]
== Layout

Stacks are `NSStackView`s and Auto Layout sizes the window, with one
exception: a stack whose children all have a size known without solving
anything places them by frame (`host/Frames.swift`). A stack is framed
when its `distribution` is `gravity`, its `align` is not `fill` (nor
`first-baseline`), its own `width`, `height` and `squeeze` are the usual
ones, the window lays out left to right, and every child (at least one) is
an element, visible, not a scroll area, list or spacer, with a `fixed`
width and height or itself a framed stack. It places them where
NSStackView would (spacing and padding along the stack; across it a
leading or top alignment keeps that edge's padding, a centred or trailing
one keeps none; slack after the last child) and reports the total as its
content size, with NSStackView's own hugging. A child with nothing to
solve (an empty box, an inner framed stack) leaves Auto Layout entirely,
since AppKit gives every view that translates its autoresizing mask four
constraints; any other keeps its frame through those. Only the outermost
framed stack takes part in Auto Layout. `sync` arranges the deepest stacks
first and again until none changes, so a stack sees its children's sizes.
A grid of 10,000 fixed-size boxes lays out in 0.09 s instead of 3.2 s
(`bench/grid`). A box draws its fill and solid border as its layer's
properties (`updateLayer`), so it has no backing store.

A batch that only repaints (`fill`, `border`, `radius`, `color`, and no
structure or text) skips layout and is only drawn. Hit testing a framed
stack searches its children by position.

[#lists]
== Lists

The table's row model follows the node tree: each engine insert, remove or
move of a row is one `insertRows`, `removeRows` or `moveRow`, inside one
`beginUpdates` per batch. A batch of more than 64 row changes (a mount, a new
query, a `CLEAR`) reloads once instead. A row's own view is its cell view
(row heights by Auto Layout, `usesAutomaticRowHeights`). A template row
inside a list is only its hole values until the table first asks for it
(`Host.materialize`): `TEXT`, `HATTR` and `HPROP` update the values, and
the row's nodes and views are made when it is first shown. A node's
children take inserts and removals in one pass when next read, so a
filter that lets a million rows back in is linear.

A windowed list (`Ui.table_list`) holds only the engine's window. The
list's own `Engine.state` holds the window, which it gives the
`table_view` and sends the host as `window-start`; the engine tells the
host how many rows the view keeps as `view-rows` on the list
(`table_view_counted`, engine patch 0006). The table has that many rows:
table row `i` is the window's row `i - start`, and a row outside the window
is a placeholder cell as high as the first row drawn (which also sets the
table's `rowHeight`, its estimate for rows not yet measured). Each row
change of the batch only marks the list; at the end of the batch it takes
its rows from the node tree, reloads the table if the row count changed,
and otherwise reloads only the rows the table holds views for whose row is
no longer the one shown (`enumerateAvailableRowViews`). When the visible
rows come within half the overscan of the window's edge (the overscan is
the visible rows, at least 20, beyond them on each side), the list sends
a `window` event, `start count`, asking for the visible rows with the
overscan around them: at most one per pass of the run loop, after a scroll
(`reflectScrolledClipView`) or a batch, and never the same window twice in
a row. A selection made on a placeholder row (arrow keys past the window)
is sent as the row's `select` once the window holds it. The first window,
100 rows from the top, covers a list opening at any height, so a list
that is not scrolled never asks.

`bench/rows` measures a list of 10,000 to 1,000,000 rows, windowed and not:
selecting, scrolling and repainting a written row cost the same at every
size. Windowed, mounting the list and clearing a filter cost the window in
the host and the engine's build of the view (the query over the table),
not a node per row; see `bench/rows/README.adoc`.

[#keys]
== Keys

The host decodes the keymaps the engine renders (property rows 4 and 5) and
matches an AppKit key event as roc-signals' design.md specifies: entries
restricted to outside text entry, exact matches in order, then physical-key
fallbacks (`KeyK`), then `every`. Ctrl, Alt and Meta match exactly; Shift
exactly except for a punctuation or symbol chord; one ASCII letter without
case. The nearest element at or above the focused view whose keymap hears
the key gets a kind-4 payload. Failing that, the most recently mounted
document handler (`Engine.on_document_key`, `Ui.shortcut`) that hears it
does. A heard `prevent` entry swallows the event, so AppKit never sees it.
Key names follow the DOM (`Enter`, `Escape`, `ArrowUp`, …) and codes the ANSI
layout.

Not done: the `stop` policy has no AppKit meaning here (one handler hears
each key), menus and their key equivalents, and `keyup` for keys AppKit
consumes itself.

== Boot and lifecycle

Before mount the host reads the program's declarations (`roc_engine_keys`:
storage keys, media queries, zone span, startup profile) and sends real boot
facts (`host/Boot.swift`, design.md Appendix B "Boot"):

[cols="1,3",options="header"]
|===
| Section | Value

| 1 location | `/`
| 2 local storage | the declared keys that exist in `UserDefaults`
| 3, 4 online, visible | true
| 6 media | `(prefers-color-scheme: dark)` / `light` from the system setting; any other query false
| 7 time | now, in ms
| 8 seed | 16 bytes from `arc4random_buf`
| 9 languages | `Locale.preferredLanguages` (1–16, each ≤ 64 bytes; `en-US` if none)
| 10 time zone | `TimeZone.current` over the declared days each side of now, with its transitions
| 11 session storage | the declared keys this process has stored
| 13 mount root | an HTML `div`, or a profile-1 program's declared root
| 14 startup | profile 0, or profile 1 fresh with no entry
|===

So `todos` saves its table under the local key `todos` and reads it back at
the next launch (`Engine.boot_storage`, `Engine.watch_changes`).

Quitting, or closing the window, cancels every effect in flight and calls
`roc_engine_drop` once; no turn runs after it. A Roc crash or a host fatal
error prints the message, shows it in an alert, then exits with status 1.
Under `ROC_SCRIPT` it never shows the alert. The modal loop runs no turns, so
a timer cannot re-enter Roc after a crash. `dbg` still prints to stderr.

[#effects-and-threads]
== Effects and threads

The page's Roc instance runs on the main thread only. An effect that blocks
or waits (HTTP and files) follows the rules below: the work leaves the
thread, Roc does not. The one other place Roc runs is a worker instance, on
its own worker thread, which follows the same rules from the other side
(xref:architecture.adoc#workers[Workers]).

. *Nothing Roc owns crosses a thread.* The `FX` operands are decoded on the
  main thread into a plain Swift value (`HttpRequest`). The engine state, the
  command and work lists and every Roc allocation stay on the main thread.
. *Work runs on the effect's own queue.* `URLSession` performs HTTP with its
  delegate on a private serial `OperationQueue`. State that queue owns (each
  transfer's buffer and redirect count) is touched only there; state the
  main thread owns (`Host.flights`: the task, its timers) only there. They
  meet in two places: the main thread hands a task over with
  `queue.addOperation`, which also resumes it, so no callback precedes the
  hand-over; the queue hands back a finished, already encoded result payload
  (`[UInt8]`: status, headers, body) with `DispatchQueue.main.async`.
. *The main thread decides whether a result exists.* A payload enters Roc
  only if its id is still tracked, by the same task. `CANCEL`, a timeout and
  teardown untrack the id _first_, then cancel the task, so a completion that
  races them is dropped on the main thread and never reaches the engine
  (which would also drop it, as stale). Even a request refused before it
  starts (a bad URL) answers one task later through the same check, so a
  `CANCEL` later in the same batch still wins.
. *One result, one turn, through the UI's queue.* Results enter through
  `Host.send`, as AppKit events do, which queues while a batch is being
  applied: a completion never re-enters Roc mid-batch.
. *Teardown cancels everything in flight* (`teardownEffects`, from
  `Host.stop` on `applicationWillTerminate`, which the scripted `quit` also
  reaches), and invalidates the session.

[#http]
=== HTTP

Timeout:: `timeout_ms` (0 = none, capped at 600 s by the engine and again by
the host) is a main-thread `Timer`. On expiry the id is untracked, the task
cancelled and `Timeout` (tag 7) delivered. URLSession's own idle timeout is
set to the same 600 s cap and, if it fires, is a `Network` error.
Body size:: The host reads at most 16 MiB (`maxHttpBodyBytes`) of a response
body, checked against `Content-Length` and as bytes arrive. Past it the
transfer is stopped and answered `Network("response body is larger than the
host's … limit")`. The protocol sets no limit for a text body.
Text:: The body crosses as tag 1's `body:rest`, which the engine requires to
be UTF-8. As Fetch's `text()` does, the host decodes it as UTF-8 with
replacement (U+FFFD) and drops a leading BOM, whatever the `charset`. Header
names are lowercased and sorted, as Fetch's `Headers` iterates them.
URLs and redirects:: Only absolute `http(s)` URLs are fetched (there is no
page to resolve a relative one against); anything else is `Network`.
Redirects are followed to `http(s)` only, at most 20 times (URLSession stops
a loop sooner, at 16); otherwise `Network`.
Request body:: Sent only for a method other than `GET`/`HEAD` and a
non-empty body, as roc-signals' runtime does.
Cache:: `Default` → `useProtocolCachePolicy`; `NoStore` →
`reloadIgnoringLocalCacheData`, and the response is not stored
(`willCacheResponse` answers nil); `Reload` → `reloadIgnoringLocalCacheData`;
`NoCache` → `reloadIgnoringLocalCacheData` too (URLSession has no
conditional-revalidation policy, so this is stricter than Fetch's);
`ForceCache` → `returnCacheDataElseLoad`.
Credentials:: A native app has no page origin, so every request is
cross-origin: `SameOrigin` sends and stores no cookies
(`httpShouldHandleCookies = false`), `Include` uses the shared cookie store.
Authentication challenges get URLSession's default handling.
Progress:: Progress (tag 26) is reported only when the engine asked for it
(`progress_ms > 0`, which it sets only for a site with a progress handler).
The queue posts each count to the main thread; there one waiting report per
request is replaced in place and delivered by one sampling timer every
`progress_ms`. Completion, cancellation and timeout discard a waiting
report, so none follows the final result. `Receiving` counts decoded bytes;
its total is `Known` only for a `Content-Length` without a
`Content-Encoding`. `Sending` reports a request body.
Not yet:: Kind 15 (a response body as a file) and kind 12 (a file as the
body) need the file heap; they remain a clear fatal error.

=== File jobs

Reads (`FX` 11), digests (13) and saves follow the same rules on a
concurrent `DispatchQueue` (`host/Files.swift`); `Host.files.jobs` plays the
part of `Host.flights`. A job checks its cancellation flag (an
`os_unfair_lock`ed `Bool`, the only state shared with the main thread)
between 1 MiB chunks, so `CANCEL` (an inspected file superseded, or its site
disposed) stops a long digest at the next chunk, and its completion is
dropped. The handle table is touched only on the main thread; `roc_dealloc`
reaching it from another thread is a fatal error.

[#files]
== Files

A file the user gives the app reaches Roc as a handle, never as bytes, as in
roc-signals (design.md, "Files"). `Ui.file_button(label, handler)` opens an
`NSOpenPanel` (several files may be chosen) and delivers a files-kind
`change` event; `Ui.drop_zone(label, handler)` is an `NSView` registered for
dragged file URLs and delivers `drop`. Both take an `Engine.FilesHandler`,
whose payload is `Received` (`{ files : List(File), refused : U64 }`).
Folders and unreadable paths are left out; no files means no event.

Handles:: The host keeps each file as a `FileEntry` (absolute path, size,
name and a media type from a short extension table, `""` when unknown) under
a token, and mints a `Box(U64)` holding the token in a fixed table of 64
slots laid out as the glue reports `Box(U64)`. The event carries the file
record `minted:u32 refused:u32 (size:u64 name:str type:str)*` and a
`List(Box(U64))` of the handles into `roc_engine_files`. Tokens encode
generation, kind and slot as `resources.zig` does, so a stale token never
resolves. A non-sandboxed app needs no security-scoped bookmark.
Release:: Roc owns the boxes. When the last `File` holding one goes, Roc
frees it with `roc_dealloc(payload - 8)`. `roc_dealloc` offers every address
to the table first (one range check), as host.zig's `blobs.route` does, and
the table retires the slot instead of freeing it. After the batch has been
applied (its `FX` and `SAVE` commands, which may name a handle Roc dropped in
the same turn, have resolved their entries), the host drains the retired
slots and drops their entries. A request keeps its own copy of the entry
until it is answered.
Bound:: 64 live handles, as in the browser host. An event with more files
than free slots delivers the ones that fit and counts the rest in `refused`.
Retired slots count until they are drained.
Reads:: For `read_bytes` and `read_utf8`, a `len` over the request's
`max_bytes` or the host's `maxFileBytes` (256 MiB, the browser default;
`ROC_MAX_FILE_BYTES` lowers it) is `FileFailed(TooLarge)`, unread. Text is
sent as tag 17 and the engine checks its UTF-8. A file that went away or
shrank is `Unreadable`.
Digests:: `sha256` is streamed through CommonCrypto (`CC_SHA256_Init`,
`_Update`, `_Final`, in libcommonCrypto, which libSystem re-exports), so the
range is never held whole. CommonCrypto rather than CryptoKit: three C
symbols in a library already linked, against a new Swift framework.
URLs:: `object_url` is a `file://` URL of the file, which an AppKit view can
load directly. A range other than the whole file has no URL of its own
natively and answers `FileFailed(Unavailable)`; the browser's limit of 16
ranges per handle does not apply.
Saves:: For `File.save` (`SAVE`), the handle is resolved while the batch is
applied, then after it an `NSSavePanel` sheet opens with the suggested name
(one at a time), and the range is copied off the main thread. As in the
browser, Roc learns nothing of the outcome; it is reported on stderr.

Not built: uploads (`FX` 12), fetched files (`FX` 15) and pasted files.

[#workers]
== Workers

A task's job (`FX` 8, roc-signals design.md "Workers" and "Prepared
state") runs in a _worker instance_: the app's own compiled module, entered
through `roc_engine_work`, `roc_engine_prepare`, `roc_engine_ask` and
`roc_engine_forget` on a worker thread (`host/Workers.swift`). The page's
instance never runs a job, and a worker instance never mounts.

[mermaid]
....
flowchart LR
    Page["page instance (main thread)"] -- "FX 8: task, input bytes, file tokens" --> Pool["WorkPool (main thread)"]
    Pool -- "JobOrder: bytes + FileEntry" --> W1["worker thread 1: instance, heap, handle table"]
    Pool -- "JobOrder" --> W2["worker thread 2 …"]
    W1 -- "JobOutcome: answer bytes + FileEntry, or a fault" --> Pool
    Pool -- "result tag 10 / 11 / 7 through Host.send" --> Page
....

=== Instances, heaps and threads

Each worker thread holds one instance at a time, and an instance is three
things only that thread touches:

Its heap:: Every allocation Roc makes on that thread. `roc_alloc`,
`roc_dealloc` and `roc_realloc` are process-wide symbols; each looks up the
calling thread's `WorkerContext` (`pthread_getspecific`, set only by worker
threads; nil on the main thread, which keeps the plain allocator). A worker
allocation carries a 32-byte link before what Roc sees (previous, next,
size, header size), so the instance's live allocations form one list that
can be freed at once.
Its handle table:: A `HandleTable` of 64 `Box(U64)` slots, like the page's.
`roc_dealloc` on a worker thread offers an address to that thread's table
only, and a page handle reaching a worker is a fatal error.
Its prepared state:: The `Box(Kept)` `roc_engine_prepare` returns, which the
thread passes to `roc_engine_ask` and back, and to `roc_engine_forget`.

Roc's reference counts are not atomic, and never need to be: no Roc value
is reachable from two threads. A job crosses to the worker as a `JobOrder`
(the payload bytes `name:str input:rest`, and the job's files as
`FileEntry` values: a path and a size); the worker builds the Roc lists and
mints its own handles for those files on its thread. The answer,
`n:u32 (token:u64)*n output:rest`, is copied out, the instance's tokens
resolved to `FileEntry` values, and the Roc list released, all on the
worker thread; the main thread gets bytes and `FileEntry` values and mints
the page's handles when it delivers result tag 10 through
`roc_engine_files` on the effect node (with no files, through
`roc_engine_event`). When the page has no free slots for an answer's files
the job is `WorkLost(ResourceLimit)` and nothing is minted.

Each worker thread has a 64 MiB stack (reserved, not committed): a job
recurses through the payload codec, up to 128 levels of the app's data, and
a secondary thread's default stack is 512 KiB.

=== The pool

`WorkPool` (main thread only) holds the worker slots, the jobs waiting for
one, and every job in flight by id, as `Host.flights` does for HTTP.

Size:: One worker per core but one, from 1 to 8:
`max(1, min(8, activeProcessorCount - 1))`. The main thread keeps a core for
AppKit and the page's turns, so a full pool never starves the UI; 8 is
roc-signals' default `maxWorkers`; the engine's in-flight bound (32 by
default) bounds the queue. Workers start when a job needs one. `ROC_WORKERS=N`
sets the size, as does the scripted step `pool:N` before any job.
Placement:: As roc-signals' pool: a job of a preparation's task runs on an
idle worker that holds its state (`ask`), or waits for a busy one that does;
any other job takes an idle worker holding nothing, a new worker while the
pool has room, or the least recently used idle holder, whose state it
replaces (`prepare`). A state is keyed by the preparation's name, its input
bytes and the page tokens and ranges of its files; when the page releases
one of those files every state keyed on it is let go (`forget`).
Stale answers:: The main thread decides whether an answer exists. A reply
counts only from a worker still in the pool, for the job it was given, and
enters Roc only while the job's id is still tracked by that job; `CANCEL`, a
timeout and teardown untrack the id first.
Cancellation:: `CANCEL` of a waiting job drops it. A running job with
`on_cancel: Stop` has its worker stopped: the slot leaves the pool at once
(a new worker takes its place when a job needs one), the thread's stop flag
is set, and the job unwinds at its next allocation or hosted call. With
`on_cancel: Finish` the job runs on and its answer is dropped, so the worker
and its prepared state are kept, until its timeout or ten minutes after it
was performed, when its worker is stopped. `on_dispose` is the engine's and
does not reach the host.
Timeouts:: A main-thread `Timer` per job (`timeout_ms`, capped at 600 s):
the id is untracked, the job dropped or its worker stopped, a finishing one
included, and `Timeout` (tag 7) delivered.
Teardown:: `Host.stop` stops every worker and drops every job; nothing is
delivered after it, and the temporary files builders wrote are removed.

=== Containment

Every call into a worker instance goes through a guarded call that
glue/SwiftGlue.roc generates (`Roc.workForHostGuarded` and so on): a C
function, `roc_guarded_<symbol>`, that takes a jump point with `_setjmp` and
calls the Roc symbol directly. Anything that must end the call
`roc_guard_unwind`s (`_longjmp`) back to it from the runtime symbol or
hosted function that met it:

* `roc_crashed`: the class from the message (`contract:`, `resource_limit:`,
  otherwise `app_crash`), and up to 512 bytes of it;
* `roc_expect_failed` (`expect_failed`), and an allocation that fails
  (`out_of_memory`);
* a job holding more than 64 handles (`resource_limit`), or a builder whose
  temporary file cannot be written (`executor`);
* a stop request (no class: the job's answer was already dropped).

The thread then frees the instance's whole heap, drops its prepared state
and replaces its handle table, so the next job runs in a fresh instance on
the same thread (a stopped thread ends instead). The job is answered
`WorkLost(class)` (tag 11), and `roc worker fault [class] in task "…": …` is
printed. The page's instance and every other worker are untouched.

Why unwinding is safe::
+
. *Only the abandoned call's own state is skipped.* The frames between the
  jump point and the unwind are Roc's and the one runtime symbol or hosted
  function that unwinds. Roc frames own no resources but heap allocations,
  which are all in the instance's list and are all freed; Roc code takes no
  locks and touches no shared mutable memory (its constants are static data,
  never written). The host frames that unwind hold no lock and no Swift
  access in progress; at worst a Swift temporary's release is skipped, a
  leak, never corruption. The jump point's frame is C, never inlined into
  Swift.
. *Nothing outside the instance can refer to what is freed.* No Roc value
  crosses threads, and the handle table, the only host structure Roc
  pointers reach, is replaced with the heap. Files the instance's handles
  named are `FileEntry` values; a builder's temporary file is removed when
  the last entry naming it goes.
. *An unwind happens only inside a guarded call on its own thread.* Each
  path checks the context's `inCall` flag; outside a call (a host bug) it
  stops the app instead. The page's instance has no context, so a crash
  there still stops the app, as before.
. *A stop never interrupts the host.* The stop flag is read only where the
  host already is (an allocation or hosted call), before it does anything,
  so a stop never lands inside `malloc` or a file write. The cost: a job
  that computes without allocating or calling an effect runs on until it
  next does or ends; its worker has already left the pool, so it holds no
  slot and its answer is dropped.

=== Hosted effects

The `roc_task_*` functions (`Hosted.roc`, reached through `Effects.roc` and
`Files.roc`) run synchronously on the worker thread, inside the job's call:
`read` reads a range of a file the job holds into a fresh list (empty when
the file can no longer be read), `size` gives a file's size, `mint` a fresh
handle, and a builder (`open`, `append`, `append_file`, `finish`) writes a
temporary file in `TMPDIR`. `append` counts against the job's output bound
(256 MiB; `ROC_MAX_OUTPUT_BYTES` lowers it) and answers 1 past it;
`append_file` and `start_from` copy the file's range and do not count.
`finish` makes the builder a file the answer may hold. Every builder a call
opened is closed when it returns (status 3 afterwards). Called outside a job
(on the page's instance) any of them is a contract error that stops the app.

== Glue

`glue/SwiftGlue.roc` writes everything the host needs to cross the ABI:

* `roc_swift_abi.h`, the Swift bridging header. Swift can call C functions
  only through a header clang imports; `@_silgen_name` uses Swift's calling
  convention, not the C ABI. The header declares `RocList` and `RocBox`, each
  record a provided procedure returns, the runtime symbols and the provided
  symbols. Record fields, padding and `_Static_assert`s of size, alignment
  and every offset come from the compiler's committed layout facts.
* `RocGlue.swift`:
** `RocList.ownedBytes` / `.bytes` / `.empty`, which encode a Roc list exactly
   as Roc does;
** for `List(Box(U64))` (the handles of a files-kind event): `RocBoxU64`, the
   box's layout (refcount word just before the payload, and the address and
   alignment Roc frees it with), and `RocList.ownedBoxesU64`, which builds the
   list. A list whose elements are refcounted carries one more header word,
   the element count, before its refcount (`allocateWithRefcount` in the
   compiler's `src/builtins/utils.zig`), so its header is 16 bytes, not 8.
   Every number comes from the compiler's layout facts (`is_refcounted`, the
   element's and payload's size and alignment). The header exposes them as
   `ROC_BOX_U64_*` constants, which the Swift helpers read, and checks them
   against the C types with `_Static_assert`s;
** one typed Swift function per provided procedure (`Roc.eventForHost(...)`),
   with its ownership contract, and its guarded twin
   (`Roc.workForHostGuarded(jump, ...)`), over the header's
   `roc_guarded_<symbol>` C trampoline and `roc_guard_unwind`
   (xref:architecture.adoc#workers[Containment]);
** `RocList.releaseBytes()`, which releases a `List(U8)` the host owns (a
   hosted function's argument, a returned answer) exactly as Roc decrements
   one;
** for the hosted functions: the C declaration of each `roc_task_*` symbol
   in the header, the `RocHostedFunctions` protocol (one typed static
   requirement each, `hostedRead(_:_:_:)` for `Hosted.read!`), and a
   `@_cdecl` export per symbol forwarding to the host's `RocHosted`, which
   must conform. The host never spells a hosted C signature.

It covers only the shapes this platform uses (byte lists, opaque boxes,
lists of boxes of an integer, integers, records of those, unit; a hosted
function takes integers and byte lists and returns one of those or a box of
an integer) and 64-bit hosts. It fails generation, naming the entry point or
hosted function, on anything else. The list helpers were the point: the stock C glue
leaves list construction to the host, and a hand-written list encoding is
easy to get wrong (see xref:contributing.adoc#findings[Constraints to build with]).

The glue serves both of the platform's architectures unchanged. Apple
silicon and Intel Macs are both 64-bit and little-endian, with the same C
layout of every shape above, and the Intel `roc` generates byte-for-byte the
glue the Apple silicon `roc` does; the Intel CI job's `glue` stage checks
that on every pull request.

[#targets]
== Targets

The platform declares three Roc targets, each with its own `libhost.a`
under `platform/targets/<target>/`, as Roc's target model expects: one
host library per target, which `roc build --target=…` links with the app's
object. They are `arm64mac` (Apple silicon), `x64mac` (Intel, x86-64-v3,
which every Intel Mac that runs macOS 15 has) and `x64v1mac` (Roc's
baseline Intel target, which `roc` picks on a machine whose CPU does not
report v3, such as Rosetta or some virtual machines). The Swift host is
compiled for each architecture with an explicit `-target`
(`arm64-apple-macos15.0`, `x86_64-apple-macos15.0`), so either Mac builds
both and the bytes do not depend on the machine; it uses no v3 instruction,
so `x64v1mac` links a copy of the `x64mac` host. All three link against the
one `targets/macos-sysroot`, whose stubs list both TAPI targets
(xref:architecture.adoc#linker-inputs[Linker inputs]).

The deployment target, macOS 15, is the oldest macOS an app runs on, and so
its `LSMinimumSystemVersion`. Roc's linker writes `minos` 11.0 into every
program, but Swift 6.2 compiling for macOS 15 references Swift runtime
symbols, such as `_swiftImmortalRefCount` and
`swift_getTypeByMangledNameInContext2`, that older macOS releases do not
export, so an earlier macOS could not load the program.

An app is universal. `macos.roc build` builds the app for `arm64mac` and for
`x64mac` and joins the two programs into one fat Mach-O file (`cli/Universal.roc`),
written byte for byte as `lipo -create` writes it, so that it needs no Apple
tool and works on Linux and Windows too: a big-endian header, then each
thin program at its CPU's page alignment, the Intel one first. Each slice
keeps the ad hoc signature Roc's linker gave it, and macOS runs the slice
for its own CPU. `LSArchitecturePriority` is left out: with both slices
native, macOS's own choice is the right one. A bare `roc build` makes one
program for one target.

[#linker-inputs]
== Linker inputs: no Apple SDK files

Following roc-gui, the platform ships no Apple SDK material. Roc's linker
links a platform's `targets/macos-sysroot`, the same one for every macOS
target: minimal TAPI v4 `.tbd` stubs written only from the reviewed catalog
`host/interfaces.json`, which records each library's install name and
evidence and each symbol's own evidence (`host/PROVENANCE.md` states what
may count as evidence and what is never read). Each stub lists both TAPI
targets, `arm64-macos` and `x86_64-macos`, and the linker reads the slice
of the architecture it links. The catalog (schema 3) names its targets in
`tapi_targets`; a symbol only one architecture exports, such as x86-64's
`objc_msgSend_stret` or `stat$INODE64`, names it in `only`, and its stub
exports it for that target alone. The platform bundle carries these
generated stubs, never an SDK file.

The stubs are an external linker input with a release of their own, as
roc-automation's "Publish linker inputs from a pull request" describes.
`scripts/link_inputs.roc` (the `link-inputs` task) writes them, with the
catalog, `PROVENANCE.md` and the licence, into a deterministic
`link-inputs-macos.tar`, which serves every macOS target, and a
`build-input-release.json` manifest that binds its SHA-256 and size (its one
asset, `macos`) to the source commit and an input fingerprint (the catalog,
the provenance statement, the licence, the producer's source and the
tooling compiler). The producer workflow `link-inputs.yml` builds it twice,
requires identical bytes, and links and runs every example against it on
an Apple silicon and on an Intel Mac; the
trusted publisher `publish-link-inputs.yml` (`actions/publish-build-inputs`)
publishes it as `linker-inputs-sha256-<manifest digest>` and commits
`link-inputs.lock.json` to the pull request. Every other build installs the
archive the lock selects (`scripts/build.roc`, cached under
`build/link-inputs-cache` and verified by size and SHA-256), and fails when
the lock's fingerprint is not the checkout's. Before the first release, with
no lock, the build generates the stubs from the catalog. After installing
them it audits each `libhost.a` against what the catalog exports for its
architecture: a reference the catalog does not own there fails the build,
so adding one is a reviewed edit that names its library and evidence.

The stubs have a second consumer: Roc's run mode. `roc main.roc` (and
`roc run`, with `--opt=dev`, the default, or `--opt=interpreter`) links the
host not with the app's object but with one of the compiler's own run shims,
`libroc_machine_code_shim.a` or `libroc_interpreter_shim.a`, which load the
program the compiler publishes into shared memory. Roc embeds both in the
`roc` binary and extracts one for every run. Their system imports (file and
mapping calls, futex waits, `dlsym`, `sys_icache_invalidate`,
`_tlv_bootstrap` and a few others) are not the host's, so the catalog lists
them as its own consumer, `run_shim`, each owned by a library with its own
evidence like any other symbol. They are the imports roc-lang/roc's
`src/machine_code_shim/archive_check.zig` allows a macOS shim, as the shims
of 0.1.0 RC1 and the nightlies of November 2026 reference them. The build
audits them as it audits the host: it carves the shims out of the `roc` it
builds with (`LinkInputs.embedded_archives`, into `build/run-shims`), takes
their `nm -u` less their own definitions and the `_roc_*` symbols the host
and the compiler's generated objects supply, and fails on an import the
catalog does not own or `run_shim` does not list; a `run_shim` name the
shims no longer import is only noted, as another supported compiler's may.
A `roc` embeds the shims of its own architecture, and they are audited
against what the catalog exports for it: the Intel `roc`'s import the libm
rounding functions (`ceil`, `floor`, `trunc` and their `f` forms) and
`__bzero`, which Apple silicon's inline, so the Intel CI job audits them.
The check's `examples` stage then runs the counter's first recorded case
through `roc main.roc`, so a run mode the stubs cannot link fails the gate.

Swift is compiled with `-disable-autolink-frameworks` and
`-disable-force-load-symbols`, so the frameworks linked are exactly the
catalog's. Roc then links each `X.framework/X.tbd` it finds. The resulting
binaries load only `AppKit`, `Foundation`, `CoreGraphics`, `libSystem`,
`libobjc` and the Swift runtime and overlays in `/usr/lib/swift`.

A Swift symbol's evidence is the declaration it mangles (Swift's
`docs/ABI/Mangling.rst`), named by the open-source demangler, in the module
the library ships; an ObjC class's is its page in Apple's documentation of
its framework.
