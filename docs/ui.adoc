= The Ui reference

Look up what each `Ui` builder draws, which props it takes and which
events it sends. For signals, stores, tables and watches, see
https://github.com/lukewilliamboswell/roc-signals[the roc-signals engine].

An app imports both modules:

[source,roc]
----
import pf.Engine exposing [Elem, Signal]
import pf.Ui
----

The builders describe controls and layout. The host renders them with
AppKit. Keyboard shortcuts and hover handlers attach behaviour to existing
views.

== How a builder reads

Most controls take a subject (text, value or selection) followed by a
*props record*. Containers take their props first and children last.
Supply required fields and any fields whose defaults you want to change.
In this view fragment, `draft` is a text signal, and `typed` and `saved` are
event handlers.

[source,roc]
----
Ui.vstack(
    { spacing: 12, align: Fill },
    [
        Ui.text("To-do", { style: LargeTitle, weight: Bold }),
        Ui.text_field(draft, { placeholder: "What needs doing?", on_input: typed, width: Fill }),
        Ui.button("Save", { on_press: saved, role: Default }),
    ],
)
----

*State is a signal; looks are values.* A field that holds what a control
shows (its text, `value`, `checked`, `enabled`, a selection) is a `Signal`. A
text literal already is one, and interpolating a signal makes one that
follows it: `Ui.text("${count} left", {})`. A field that says how something
looks (spacing, text style, colour, size) is a plain value. When a look must
follow state, the `_s` form of a look-only builder takes the whole props
record as a signal:

[source,roc]
----
Ui.text_s(total, over.map(|o| if (o) { color: Red, weight: Bold } else {}))
----

`text_s`, `vstack_s`, `hstack_s`, `box_s`, `image_s` and `asset_image_s` exist; a control's
props already hold signals and handlers, so controls have no `_s` form, and
neither do `scroll`, `list` and `table_list`, whose sizes the window takes over once open.

Handlers are fields too: `Ui.button("Save", { on_press: h })`.

[#drawing]
== Drawing

`Ui.surface` draws a scene: an ordered list of marks, in one native view.
The scene is a signal, so a plot that follows state is a `map`:

[source,roc]
----
Ui.surface(
    points.map(|ps| [
        Fill(Rect({ x: 0, y: 0, width: 320, height: 160 }), Adaptive({ light: 0xf4f4f4, dark: 0x202020 })),
        Stroke(Polyline(ps), { color: Green, width: Value(2) }),
    ]),
    { label: "Temperature", space: Engine.const(Fit({ width: 320, height: 160 })) },
)
----

A new scene redraws that one view. There is no view per shape and no layout
pass, so a scene can change at every turn.

*Marks*, drawn in order:

* `Fill(shape, color)` and `Stroke(shape, { color, width })` draw a shape.
  Strokes have round joins and caps. The width is a number
  (xref:ui.adoc#surface-sources[Native sources]), `Value(2)` or one a source
  drives; a width below 0 draws nothing.
* `Translate(x, y)`, `Rotate(radians)`, `Scale(x, y)` and
  `Matrix({ a, b, c, d, tx, ty })` move everything drawn after them.
  `Opacity(amount)` multiplies its opacity.
* `Save` keeps the current transform and opacity, and the matching `Restore`
  returns to them.

*Shapes:* `Rect` and `Oval` of an `Area` (`{ x, y, width, height }`),
`Polyline` and `Polygon` of `Point`s, and `Path` of segments (`MoveTo`,
`LineTo`, `QuadTo`, `CurveTo`, `Close`).

*Coordinates.* With the default `space: Points`, one unit is one point,
from the surface's top-left corner, with y down and positive angles
clockwise. Points are AppKit's units: the surface draws at the screen's
backing scale (2 pixels a point on a Retina display), so lines stay sharp.
With `Fit({ width, height })`, a `width` by `height` scene is scaled to the
largest size that fits the surface without distortion, and centred. It
follows the surface as the window resizes, and line widths scale with it.
Whatever falls outside the surface is clipped.

*Bounds.* A coordinate, size or width must be a finite number within
±1,000,000 units. A frame may draw at most 65,536 points, counting every
series. A scene outside these bounds, or a `Restore` without a `Save`,
stops the app with an error naming the line of the scene.

[#surface-sources]
=== Native sources

A number in a scene is a constant, `Value(n)`,
`Source({ source, scale, offset })`: the latest scalar of a native source,
read as `offset + scale * value`, or
`Element({ source, index, scale, offset })`: the value at `index` (from 0)
of a source's latest series, read the same way, so one band of
`"audio.bands"` can move a mark. An index past the end of the series reads
0, so the number is `offset`. Four shapes draw sources' latest series
of numbers (at most 4,096). Each value `v` counts as
`t = (v - low) / (high - low)`:

* `Wave({ source, area, low, high })` is a polyline across the area, with
  `t` 0 on its bottom edge and 1 on its top.
* `Ring({ source, x, y, radius, depth, low, high })` is a closed polyline
  around a centre, starting at the top and going clockwise, each point
  `radius + depth * t` out.
* `Bars({ source, area, low, high, gap })` is one bar per value, `gap`
  apart, each rising from the bottom edge to `t` of the height (`t` is held
  between 0 and 1).
* `Lissajous({ across, down, area, low, high })` plots one series against
  another, value by value: `t` of `across` from the area's left edge (0) to
  its right (1), and `t` of `down` from its bottom edge to its top. With
  `audio.left` and `audio.right`, turned 45 degrees with `Rotate`, it is a
  stereo vectorscope.

A source is named by a stable string, such as `"audio.waveform"`. It is
native code that registers that name (xref:architecture.adoc#surface-sources[Surface sources]).
The playback session (xref:ui.adoc#audio[Audio]) registers
`audio.waveform` (1024 values of the channels mixed, -1 to 1, oldest
first), `audio.left` and `audio.right` (each channel alone, the same way; a
mono source's are both its one channel), `audio.bands` (the 24 bands, 0 to
1), and the numbers `audio.level`, `audio.bass`, `audio.mids` and
`audio.treble` (0 to 1). Each reads the measurement nearest what is heard,
-60 to 0 dB mapped to 0 to 1, rising at once and falling slowly.
A source that is not registered, or has nothing to show yet, draws nothing,
and its number reads as `offset`. Every app has two test sources:
`synthetic.wave`, nine values of one sine cycle, and `synthetic.level`, a
number from 0 up to 1. They move on with time, and a spec steps
them (xref:apps.adoc#surfaces-and-audio[Drawing surfaces and audio]).

*Pacing.* `pacing: OnDemand` (the default) draws a new frame when the
scene, its look or its size changes. `Display` also draws one at every
refresh of the display, reading its sources each time, with no turn of the
engine. It does this only while the surface is in a window and not hidden,
so removing it stops the work. A refresh the Mac was too busy for is skipped,
not queued. Each frame has a time on a monotonic clock, and the next frame
covers the time since. On a display-paced surface, a scene change shows
from the next refresh.

=== Trails

`trail: Trail({ half_life_ms, zoom, turn, shift })` draws each new frame over
the previous one. The previous frame first fades, so that after
`half_life_ms` it has half its opacity. It also grows by `zoom` each second
(1 for none), turns by `turn` radians a second (both about the surface's
centre), and moves `shift` points a second. Then the scene is drawn over it.
These are rates, so a trail lasts as long at 60 Hz as at 120 Hz:

[source,roc]
----
# Rings that zoom away and fade by half every 300 ms.
trail: Engine.const(Trail({ half_life_ms: 300, zoom: 1.4, turn: 0, shift: { x: 0, y: 0 } }))
----

Each frame is drawn in this order:

. The background colour.
. The previous frame, moved and faded. Where the moved frame no longer
  covers the surface, the background shows.
. The scene.

A repaint of the same frame (a window drawn again) never fades it again.

The trail starts empty when the surface first appears, and empties again
when its size or backing scale changes, when `trail` is turned on or off,
and whenever `reset` takes a new value. Bump a counter in `reset` to clear it
on a seek or a new track. The trail is kept in two bitmaps however long it
lasts, and they are released when the surface is removed. A display-paced
surface draws with Metal when the Mac has a GPU, at the screen's full
resolution. Otherwise, and for an on-demand surface, it draws with Core
Graphics, which keeps a large surface's trail at below the screen's backing
scale, so it looks a little softer. See
xref:architecture.adoc#drawing-surfaces[Drawing surfaces].

[#shaders]
=== Shaders

A display-paced surface can run its own GPU code, in two stages shaped
like a feedback visualizer's:

[source,roc]
----
shader : Signal(ctx, Ui.Shader)   # a SurfaceProps field, NoShader by default
Ui.Shader : [NoShader, Shaders({ warp : [None, Some(Str)], composite : [None, Some(Str)], params : List((Str, Number)) })]
----

Each frame is then drawn in this order:

. *Warp.* With a `warp` stage, each pixel of the new frame is what the
  warp returns, reading the previous frame (`f.image`): motion, decay,
  colour drift. The warp takes the trail's place; without one, the
  background and the trail are drawn as usual.
. *The scene.* The marks are drawn over it.
. *Feedback.* The result is kept as the next frame's `f.image`.
. *Composite.* With a `composite` stage, each pixel on the screen is what
  the composite returns, reading this frame (`f.image`): echo, gamma, glow,
  a kaleidoscope. Its output never feeds back. With `composite` alone and no
  trail, the frame under it is the scene over the background, drawn fresh.

*What you write.* Each stage is Metal Shading Language source that defines
one function, `float4 warp(Frame f, Params p)` or
`float4 composite(Frame f, Params p)`, and any helper functions and
constants it needs above it. The host compiles it at run time between its
own header (below) and its own entry point, which calls yours once for
each pixel. Return a premultiplied colour, each channel 0 to 1 (out of
range is held to it, a NaN reads 0, and no channel can exceed the opacity);
`opaque(rgb)` makes an opaque one. Lines and columns in errors count from
the first line of your source.

[source,roc]
----
# A warp that zooms the old picture towards the viewer, faster on a kick,
# fading it a little each frame and drifting its hue.
zoom =
    \\float4 warp(Frame f, Params p) {
    \\    float2 c = centered(f);                       // -1..1 tall, aspect wide
    \\    float scale = 1.0 - p.push * f.bass;          // < 1 grows the picture
    \\    float4 old = sample(f, uv_of(f, c * scale));
    \\    float3 hsv = rgb2hsv(old.rgb);
    \\    hsv.x += 0.3 * f.dt;                          // hue turns 0.3 a second
    \\    return opaque(hsv2rgb(hsv) * pow(0.5, f.dt / p.half_life));
    \\}

shader: Engine.const(Shaders({ warp: Some(zoom), composite: None, params: [("push", Value(0.04)), ("half_life", Value(0.4))] }))
----

*A frame* (`Frame f`) gives each pixel:

[cols="1,3",options="header"]
|===
| Field | Is

| `f.uv` | the pixel's centre, 0 to 1 across and down from the top-left corner (y down, as a scene's)
| `f.pixel`, `f.size`, `f.texel` | the pixel and the surface in pixels, and one pixel in uv units (`1 / size`)
| `f.aspect` | width over height
| `f.time`, `f.dt`, `f.frame` | seconds since these shaders started, seconds since the previous frame, and the frame's number from 0; make motion a rate of `dt` so it looks the same at 60 Hz and 120 Hz
| `f.bass`, `f.mids`, `f.treble`, `f.level` | `audio.bass`, `audio.mids`, `audio.treble` and `audio.level`, 0 to 1 (0 with nothing playing)
| `f.image` | the previous frame (warp) or this frame (composite); read it with the helpers below
|===

*Helpers* in the header:

* `sample(f, uv)` reads `f.image` (beyond its edges, the nearest edge);
  `sample_wrap` tiles it and `sample_mirror` tiles it mirrored;
  `blur(f, uv, radius)` blurs over about `radius` pixels.
* `wave(f, x)`, `left(f, x)`, `right(f, x)`: `audio.waveform`, `audio.left`
  and `audio.right` at `x`, 0 the oldest and 1 the newest, -1 to 1 (256
  points, interpolated); `band(f, x)`: `audio.bands` from 0 (40 Hz) to 1
  (16 kHz), 0 to 1; `band_at(f, i)`: band `i`, 0 to 23.
* `centered(f)`: the pixel from the centre, y from -1 at the top to 1 at
  the bottom and x on the same scale; `uv_of(f, p)` goes back.
  `polar(p)` is `(distance, angle)`, `cartesian(ra)` goes back, and
  `rotate(p, angle)` turns clockwise; `PI` and `TAU`.
* `hsv2rgb`, `rgb2hsv`, `palette(t, a, b, c, d)` (`a + b cos(TAU (c t + d))`)
  and `opaque(rgb)`.
* `hash(p)` (repeatable noise, 0 to 1), `noise(p)` (smooth value noise) and
  `fbm(p)` (four octaves of it).

*Params.* `params` are named numbers each stage reads as `p.NAME`, a
`float`. Each is a scene `Number`, so `Source({ source: "audio.bass", … })`
or `Element(…)` drives it, read once a frame without a turn of the engine.
A name is lowercase letters, digits and `_`, not starting with a digit, at
most 32 bytes; there are at most 16, and a source of a stage is at most
64 KiB.

*Compiling and errors.* A source compiles the first time a surface draws
with it, off the main thread, and the result is kept for the app's life,
keyed by the whole source, so switching back is immediate. Until it is
ready the surface keeps drawing its last good stage, or none. `on_shader`
hears what the stages are doing, each time it changes:

[source,roc]
----
on_shader: Handled(Engine.handle(|status| [cells.shader.set(status)]))

Ui.ShaderStatus : [NoShader, Running, Fallback, Failed(List(Ui.ShaderError))]
Ui.ShaderError : { stage : [Warp, Composite], line : U32, column : U32, message : Str }
----

`Failed` lists each stage's first errors at their line and column in that
stage's source; line 0 is outside it, such as a missing `warp` function or
a bad param name. A stage that fails keeps drawing its last good source (or
none), and the other stage runs. Bad source never stops the app.

*The GPU's limits.* A frame the GPU is more than two frames behind on is
skipped, so a slow shader makes the picture slow, never the window. A shader
that runs for seconds is stopped by macOS's GPU watchdog: that frame is
lost, the surface drops both stages and draws its marks and trail alone, and
`on_shader` hears `Failed` with line 0 and the GPU's reason, until the app
gives it new sources. Keep loops bounded and short: a full-surface stage
runs once for every pixel, millions a frame on a Retina display.

*Where shaders do not run.* Shaders run only with the Metal renderer, on a
display-paced surface while it is shown. With Core Graphics (an on-demand
surface, a Mac without a GPU, `ROC_SURFACE_RENDERER=cg`, a spec that does
not ask for Metal), the surface draws its marks and its trail as if it had
no shaders, and `on_shader` hears `Fallback`. Give a shaded surface a scene
and a trail that look reasonable alone: they are its simpler picture.

`examples/visualizer`'s `Shaders` mode has a test of each stage, and its
`Gallery` plays a file through twelve visualizations kept as data in
`src/Presets.roc`: each a name, a description, its shaders (commented, to
learn from), its params with their ranges, and the scene and trail it
draws with Core Graphics. Another app adopts them by copying that module.

=== Overlays

`Ui.overlay(props, background, foreground)` puts native views over a
surface: captions, lyrics, a legend. The background fills the overlay and
sizes it. The foreground sits inside `padding`, placed by `horizontal` and
`vertical`: `Fill` stretches it to that side, and the others hug it. The
foreground is ordinary AppKit views, so its text wraps, it can scroll (put a
`Ui.scroll` in it), and VoiceOver reads it. It is never part of the
surface's picture, so it never enters a trail:

[source,roc]
----
Ui.overlay(
    { vertical: Bottom, padding: All(12) },
    visualizer,
    Engine.when(show_lyrics, || Ui.box({ fill: Adaptive({ light: 0x000000, dark: 0x000000 }) }, Ui.text(line, { overflow: Wrap, align: Center, width: Fill })), || Engine.text("")),
)
----

The background must always be an element. The foreground may come and go.

[#ui-looks]
== Looks

The shared types, all inside `Ui` (`Ui.Length`, `Ui.Color`, …):

[cols="1,3",options="header"]
|===
| Type | Values

| `Length` | `Auto` (natural size), `Fill` (the room its stack offers on that side), `FillAtLeast(n)` (fill, never under `n`), `Fixed(n)`, `AtLeast(n)`, `AtMost(n)`, `Between({ min, max })`
| `Squeeze` | `Standard`, `Yield` (truncates or shrinks before its neighbours), `Resist` (after them)
| `Insets` | `Zero`, `All(n)`, `Axes({ horizontal, vertical })`, `Each({ top, leading, bottom, trailing })` (each defaults to 0: `Each({ top: 8 })`)
| `HorizontalAlign` | `Leading`, `Center`, `Trailing`, `Fill` (stretch each child to the stack's width)
| `VerticalAlign` | `Top`, `Center`, `Bottom`, `FirstBaseline`, `Fill`
| `Distribution` | `Gravity` (AppKit's default), `Fill`, `FillEqually`, `FillProportionally`, `EqualSpacing`, `EqualCentering`
| `TextStyle` | `LargeTitle`, `Title1`, `Title2`, `Title3`, `Headline`, `Subheadline`, `Body`, `Callout`, `Footnote`, `Caption1`, `Caption2`: AppKit's text styles
| `FontSize` | `Standard` (the style's size) or `Fixed(n)` points, for a display such as a stopwatch
| `Weight` | `Standard` (the style's own), `Light`, `Regular`, `Medium`, `Semibold`, `Bold`, `Heavy`
| `Design` | `Proportional`, `MonospacedDigits` (changing numbers keep still), `Monospaced`
| `TextOverflow` | `Clip`, `TruncateHead`, `TruncateMiddle`, `TruncateTail`, `Wrap`, `WrapUpTo(lines)`
| `TextAlign` | `Natural`, `Leading`, `Center`, `Trailing`, `Justified`
| `Color` | AppKit's semantic colours: `Label`, `SecondaryLabel`, `TertiaryLabel`, `QuaternaryLabel`, `Accent`, `Link`, `PlaceholderText`, `Separator`, `WindowBackground`, `ControlBackground`, `UnderPageBackground`, `TextBackground`, `SelectedContentBackground`, `Red`, `Orange`, `Yellow`, `Green`, `Mint`, `Teal`, `Cyan`, `Blue`, `Indigo`, `Purple`, `Pink`, `Brown`, `Gray`, `Clear`; and `Adaptive({ light, dark })`, two `0xRRGGBB` values
| `ControlSize` | `Mini`, `Small`, `Regular`, `Large`
| `Bezel` | `Push`, `FlexiblePush`, `Toolbar`, `AccessoryBar`, `Badge`, `Circular`, `SmallSquare`, `Borderless`
| `ButtonRole` | `Normal`, `Default` (answers Return, drawn in the accent colour), `Cancel` (answers Escape), `Destructive`
| `Icon` | `NoIcon` or `Symbol(name)`: an SF Symbol beside a title
| `TitleDisplay` | `Visible` or `Hidden`; a hidden title still names the control to VoiceOver, so an icon-only button keeps one: `Ui.button("Remove", { on_press, icon: Symbol("trash"), title_display: Hidden, bezel: Borderless })`
| `Border` | `NoBorder`, `Line({ color, width })`, `Dashed({ color, width })`
| `SymbolScale` | `Small`, `Medium`, `Large`
| `ImageScaling` | how an asset image fits a frame of another shape: `Fit` (all of it, letterboxed), `Fill` (covers the frame, cropped), `Stretch` (distorted to the frame), `Original` (its own size, centred and clipped)
|===

Semantic colours follow light and dark mode, increased contrast and the
user's accent colour with no code in the app. `Adaptive` is the escape hatch
for a colour of the app's own: it names one for light windows and one for
dark ones, so it is never wrong in either.

A wrapping text (`overflow: Wrap` or `WrapUpTo(n)`) has no width of its own:
give it one (`width: Fill`, or a bound) and it wraps to it.

Deliberately not styleable: font families and arbitrary sizes beyond
`Fixed`, the colours of controls themselves (bezels, focus rings, selection),
shadows, gradients, opacity, animation, absolute positions and per-side
borders. AppKit draws controls to match the system. There is no cascade: a
text inside a box does not inherit anything from the box, so one call site
says everything about its element.

== Themes

A look is a value, and sharing one is ordinary Roc: keep props values in a
record and pass them, or update one with `{ ..theme.card, padding: All(16) }`.

[source,roc]
----
Theme : { page : Ui.VStackProps, quiet : Ui.TextProps, panel : Ui.BoxProps }

theme : Theme
theme = {
    page: { spacing: 14, align: Fill, width: AtLeast(440) },
    quiet: { style: Subheadline, color: SecondaryLabel },
    panel: { border: Line({ color: Separator, width: 1 }) },
}

Ui.box({ ..theme.panel, padding: All(28) }, Ui.text("Nothing to do", theme.quiet))
----

*Annotate a shared props value* (`theme : Theme`, or `card : Ui.BoxProps`).
An unannotated record literal is its own closed record and does not take
the props' defaults, so it fails to type-check where the props are expected.

== Events

[cols="1,1,2",options="header"]
|===
| Builder | Event | When, and what the handler receives

| `button` (`on_press`) | `click` | an `Engine.Click`
| `text_field`, `text_area` (`on_input`) | `input` | the whole text, on every edit
| `slider` (`on_input`) | `input` | the new whole value, as text, while it is dragged
| `checkbox` (`on_change`) | `change` | its new state
| `dropdown`, `segmented`, `tabs` (`on_change`) | `change` | the chosen title
| `row` (`on_select`) | `select` | the user selects the row
| `form` (`on_submit`) | `submit` | Return in one of its text fields, or a click on its `submit_button`
| `shortcut` (`on_key`) | `keydown` | the `Engine.Key`; compare its `heard` with a chord to tell several apart
| `file_button` (`on_files`) | `change` | the chosen files, as `Engine.Received`
| `drop_zone` (`on_drop`) | `drop` | the dropped files, as `Engine.Received`
| `hover` (`on_hover`) | `hover` | `True` when the pointer enters its child, `False` when it leaves it or the window
|===

`Ui.hover` wraps any element without adding a view, so wrapping a grid's
every cell costs no more views than the cells:

[source,roc]
----
Ui.hover(
    { on_hover: Engine.handle(|inside| [cells.pointed.set(if inside "Red" else "")]) },
    Ui.box({ fill: Red, width: Fixed(26), height: Fixed(26) }, Ui.spacer()),
)
----

Hover follows the pointer as a browser's `mouseenter` and `mouseleave` do. A
hover inside another hears its own enter and leave while the outer one stays
entered. Moving within one element sends nothing; crossing from one to
another sends the leave, then the enter, and the window is laid out once
after both. The host hit-tests each mouse move once, from one tracking area
for the whole window, so the cost of a move follows the depth of the tree,
not the number of hover targets. A drag (a move with a button down) and a
layout change under a still pointer are not hover moves; the next move
catches up. A `list`'s rows must be `row`s: hover inside a row, not around
one.

A control's state comes from its signals: a text field shows its subject, a
checkbox its `checked` signal. Write the new value in the handler, as
`Ui.text_field(cells.url.signal(), { on_input: Engine.handle(|typed| [cells.url.set(typed)]) })`
does.

[#the-window]
== The window

Without a scroll area or a list, the window fits its content exactly; give
the top stack a `width: AtLeast(n)` for a comfortable minimum. Once a scroll
area or list appears, the window opens tall enough for its
`opening_height`, and from then on grows only when the content around it
needs more room. The user can resize the window; the scroll area takes the
slack, within its `height`.

The window never grows past its screen: it keeps within the screen's
visible frame (less the menu bar and the Dock), and fits it again when it
moves to another screen or the screens change. Content that needs more
than that is not cut off: the whole window scrolls, as a page does, and the
window can be made no smaller than its content needs or its screen has
room for. A layout that suits small screens gives what is tall a scroll
area of its own, so that part scrolls, not the window, as the starter's
panels do.

== Lists

`Ui.table_list(props, table, { query, plan }, template)` lists the rows of
a table in an `NSTableView`: the rows of an `Engine.table_view` of `table`
with that `query` and `plan`, each drawn by `template` as a `Ui.row`. The
list keeps the view's window itself: the engine draws only the rows around
those on screen (a screenful or more on each side), the table is sized for
every row the query keeps, and as the user scrolls the list moves the window
and the engine draws the rows that come into it. A row outside the window
shows as an empty row of the same height until it is drawn, which is rarely
long enough to see. So mounting the list, holding it and a filter that lets
many rows in or out cost the rows drawn, not the table: a million rows open
in about the time the engine takes to build its view of them. The template
runs in the list's context, `Engine.In(ctx, Engine.Window)`: cells read and
write there as anywhere, and a signal of the enclosing context enters with
`lift`.

[source,roc]
----
Ui.table_list(
    { width: Fixed(300) },
    cells.contacts,
    { query: cells.search.signal(), plan },
    |key, contact| row(key, contact),
)
----

Selecting a row, moving the selection with the arrow keys (into rows not
drawn yet: the selection reaches the engine once they are) and a `select:`
script step work as in any list; `select:<text>` finds a row among those
drawn.

`Ui.list({}, rows)` puts any rows, an `Engine.table_view` (with a `window`
of the app's own, or `Engine.every_row`) or an `each` of `Ui.row`s, in an
`NSTableView`. AppKit draws only the rows on screen, and a row's views are
made when it is first scrolled into sight, but the engine draws every row
its `window` holds: 10,000 rows cost the engine and the host a small node
each. Each row the engine inserts, removes or moves is one incremental
change to the table. See xref:architecture.adoc#lists[Lists] for the costs.

`Ui.scroll` suits short lists and mixed content: it is a stack, and every
element in it gets its views.

== Keys

`Ui.shortcut([Ui.command("n")], { on_key: Engine.handle(|_key| ...) })` hears Command-N
when no control's own key handler did, and prevents its default. Key names
follow the DOM (`Enter`, `Escape`, `ArrowUp`, …). A control's own key
handler, through `Engine` keymaps, hears keys while it or a view inside it
has focus. Menus and their key equivalents are not built yet.
xref:architecture.adoc#keys[Keys] gives the matching rules.

== Effects

Effects are asks issued by a watch site (`Engine.watch`, `Engine.watch_latest`,
`Engine.watch_changes`) and answered as a turn. Use `watch_latest` for
anything that starts and stops, such as an interval: plain `watch` never
cancels what it issued.

HTTP:: `Engine.http({ url, timeout, cache, ... })` through `URLSession`, with
timeouts, cancellation and transfer progress
(`Engine.react(...).with_progress(...)`). Only absolute `http` and `https`
URLs are fetched, a response body is limited to 16 MiB, and the body is
decoded as UTF-8. xref:architecture.adoc#http[HTTP] has every bound and
mapping.

Timers:: `Engine.timer(ms)` and `Engine.interval(ms)`.

Local storage:: `UserDefaults`. Declare the keys in
`Engine.program_store({ storage_keys: ["todos"] }, ...)`, read them at boot
with `Engine.boot_storage(boot, "todos")` and write them with
`Engine.command(StorageSet("todos", text))`. A bare binary and its `.app`
bundle keep separate domains (`todos` and the bundle identifier), so they do
not share saved values. Session storage lasts for the life of the process.

Files:: A file the user gives the app reaches it as a `File` handle, never as
bytes. `file_button` (several files may be chosen) and `drop_zone` deliver
`Received`, `{ files : List(File), refused : U64 }`. Folders and unreadable
paths are left out, and no files means no event. The app may hold 64 files
at once; more in one event are counted in `refused`. A handle is released
when the last `File` holding it goes. On a file: `sha256` streams a digest;
`read_bytes` and `read_utf8` read it, up to 256 MiB (`FileFailed(TooLarge)`
past that); `slice` narrows it to a range; `object_url` gives a `file://` URL
of the whole file (`FileFailed(Unavailable)` for a range); and `File.save`
opens a save panel with a suggested name. The app learns nothing of a save's
outcome. Uploads, fetched files and pasted files are not built.

Workers:: See xref:ui.adoc#workers[Workers] below.

Audio:: See xref:ui.adoc#audio[Audio] below.

Not built:: crypto keys, and ports of an app's own: the host serves the
platform's audio ports and no others.

[#audio]
== Audio

`Audio` plays one local audio file natively, with a transport, a 10-band
EQ and opt-in measurements of the signal. The host serves it as typed ports
(roc-signals' `Port`), so an app declares them once, sends commands from an
effect plan and follows subscriptions from watch sites:

[source,roc]
----
import pf.Audio
import pf.Engine

main = Engine.program_store({}, |_| store, |_| view()).with_ports(Audio.ports)

## A press posts commands, in order, to an outbox cell…
play = Engine.handle(|_| [cells.outbox.update(|box| box.post([Play]))])
load = Engine.handle_by(cells.track.signal(), |track, { files, .. }|
    match files.first() {
        Ok(file) => [cells.track.set(track + 1), cells.outbox.update(|box| box.post([Load({ track: track + 1, file })]))]
        Err(_) => []
    })

## …which one site sends.
Engine.on_post(cells.outbox.signal(), |commands| commands.map(Audio.send), Engine.ignore({}))

## What happened, where playback stands, and (while checked) measurements.
Engine.watch(Engine.const({}), |_| [Audio.events({})], Engine.react(|_, event| …))
Engine.watch(Engine.const({}), |_| [Audio.status({ every_ms: 200 })], Engine.react(|_, status| …))
Engine.watch_latest(cells.measuring.signal(), |on| if (on) [Audio.analysis({ every_ms: 100 })] else [], Engine.react(|_, snapshot| …))
----

`examples/player` is a whole player: a file button and a drop zone, the
transport, a seek and a volume slider, the EQ's sliders, Bypass and Flat,
and a level readout.

Commands:: `Load({ track, file })` opens a whole `File` (a slice is
`Failed(Unsupported(…))`) and stops at its start; `track` is the app's own
number for it, which every event and status carries. The host keeps its own
reference to the file while it is loaded, so dropping the handle does not
stop playback, and the handle still counts against the 64 an app holds only
while the app holds it. `LoadAsset({ track, path })` opens a file the app ships in its `assets/` (`"song.mp3"`), found as `Ui.asset_image` finds an image (`ROC_ASSETS`, the `.app`'s `Resources/assets`, then `assets/` beside the program or in the working directory), and behaves as `Load` does, with the same events; it holds no file handle, so it never counts against the 64, and a path that leaves `assets/` or names nothing there is `Failed(Unsupported(…))`. `Play` plays from where playback stands (from the
start after `Ended`); `Pause` holds the playhead and `Resume` continues;
`Stop` lets go of what is scheduled and goes back to the start; `Seek(ms)`
moves the playhead, clamped to the duration: playing goes on playing, paused
stays paused, stopped stays stopped. `Volume(v)` is the output volume, 0 to
1. `VisualOffset(ms)` shows the measurements a drawing surface reads, and
`Audio.analysis` sends, `ms` milliseconds later than the sound they measure,
-500 to +500 (positive when the picture leads what the listener hears,
negative when it trails). The session already allows for the latency the
output reports; the offset is for what an output does not report, such as
a Bluetooth speaker or a TV, so keep one per `Status.output` and send it
when the output changes (the starter's EQ panel does, under Picture sync).
`Close` lets go of the file and the audio engine. Commands take effect in
the order they are sent: a seek after a load seeks the new source.
Events:: `Audio.events({})` delivers `Loaded({ track, duration_ms, frames,
sample_rate, channels })`, `Failed({ track, error })` and `Ended({ track })`,
up to 64 waiting while the app is busy. `Ended` is natural completion,
delivered once per start: a seek, a stop or a new load discards any
completion of what came before, so an `Ended` never names an older source.
An error is recoverable (load another file): `Unsupported(why)` for a format
the decoder does not play (Core Audio's `typ?` or `fmt?`) or a slice,
`Corrupt(why)` for a file that is not the audio it claims to be, and
`Output(why)` when the audio output cannot start.
Status:: `Audio.status({ every_ms })` delivers `{ track, generation, state,
position_ms, duration_ms, volume, latency_ms, visual_offset_ms, output, eq }` when it subscribes, on
every change, and every `every_ms` (16 to 60,000; the player uses 200, five
a second) while playing; only the newest waits. `state` is `Idle`, `Loading`,
`Stopped`, `Playing`, `Paused` or `Ended`. Times are milliseconds on the
source's timeline: `position_ms` is where playback has rendered to, and a
sample is heard `latency_ms` after it: the output's latency as Core Audio
reports it (the device's and its stream's, 21 ms on a MacBook Air's
speakers), which the measurements a surface reads already allow for.
`visual_offset_ms` is the `VisualOffset` that applies, and `output` the
device playing, `{ name, uid }`: its name as Sound settings show it and its
Core Audio UID, which stays the same across launches (both empty under a
spec's manual clock). `generation` changes with every load, seek, stop and
restart, as a drawing surface's reset signal.
EQ:: Ten one-octave bands centred at `Audio.band_centres_hz`, 32, 64, 125,
250, 500, 1000, 2000, 4000, 8000 and 16,000 Hz. `Gain({ band, db })` sets
band 0 to 9 within -12 to +12 dB; `Preamp(db)`, the gain before the bands for
headroom, within -24 to +12 dB; `Bypass(on)` plays the unprocessed signal at
the same volume and keeps the settings for when it is off; `Flat` sets every
band and the preamp to 0 dB. The EQ starts flat, at unity. A value out of
range is clamped, and the status reports what applies; a value that is not a
number is ignored; a band outside 0 to 9 is a host error. A band whose
centre is above 45% of the source's sample rate (16 kHz below 35.6 kHz) is
bypassed and keeps its gain. Changes take effect at once and never move the
playhead.
Measurements:: `Audio.analysis({ every_ms })` turns the measurements on for
as long as it lives (unchecking the player's box ends it, and the last
subscription to go turns the work off), and delivers at most every
`every_ms` the newest snapshot of the current source position: `{ track,
at_ms, rms_db, peak_db, bands_db, envelope }`. They measure the signal after
the EQ and before the volume, so a cut shows and a low volume does not. A
window is 2048 samples at the source's rate (43 ms at 48 kHz, 46 ms at
44.1 kHz), one every 512 samples, and `at_ms` is its centre on the source
timeline. `rms_db` is the mean-square level with the channels' powers
averaged (a full-scale sine reads -3 dBFS) and `peak_db` the largest sample;
`bands_db` is the energy in each of 24 bands, logarithmically spaced from
40 Hz to 16 kHz (`Audio.band_edges_hz`), from a Hann-windowed 2048-point FFT
with the channels' powers averaged (so opposite-phase stereo still reads),
in dB relative to a full-scale sine all in one band; `envelope` is the
window's mono signal as 32 min/max pairs. Silence and a band above half the
sample rate read -120 dB, never infinity. Only the first two channels are
measured. A seek, a stop or a new source discards the old measurements, and
nothing is sent while paused or ended.

[#workers]
== Workers

A computation that would hold up the window runs as a worker task: a Roc
function whose jobs run on a background thread, in an instance of the app
of their own, while the window goes on answering. The API is roc-signals'
`Worker` module, unchanged.

[source,roc]
----
import pf.Engine
import pf.Files
import pf.Worker

## A task: a namespaced name and what a job does with its input.
count : Worker.Task(Str, U64, Worker.Never)
count = Worker.task({ name: "example.org/words/count", run!: |text| Ok(text.split_on(" ").len()) })

## Register every task once, on the program.
main = Engine.program_store({}, |_| store, |_| view()).with_workers([count.registration()])

## Ask for a job from a watch site; the answer is a result like any other.
Engine.watch_latest(cells.text.signal(), |text| [count.ask(text)], Engine.react(|_, res| [cells.words.set(res ?? 0)]))
----

* A task's input, output and error cross as bytes the compiler derives from
  their types (`Wire.Sendable`: numbers, `Bool`, `Str`, lists, sets,
  dictionaries, records, tuples, tags and `File` handles). Send bulk bytes
  as `Wire.Bytes`. A task that cannot fail names its error `Worker.Never`.
* The answer is `Try(output, Worker.Error(error))`: `Failed(error)` is the
  task's own; `Timeout`, `Refused`, `TooDeep`, `NanKeys`, `TooManyFiles`
  and `Lost(fault)` are the platform's. A job that crashes is
  `Lost(AppCrash)` (or `Contract`, `OutOfMemory`, …): only that job is lost,
  the app keeps running, and the next job runs in a fresh instance.
* `Worker.resource`, `Worker.resource_when` and `Worker.gather` follow a
  task's answers for an input, or for one job per shard; `watch_latest` and
  `ask` work as for any effect. A new input stops the job for the old one.
* `timeout: Ms(n)` stops a job that has not answered in `n` ms (`Timeout`).
  `on_cancel: Stop`, the default, stops a cancelled job's worker;
  `on_cancel: Finish` lets the job complete and drops its answer, keeping
  the worker and any prepared state. `on_dispose: Keep` keeps a job running
  when its site goes.
* `Worker.preparation` and its `task`s share an expensive first step: a
  worker that prepared an input may keep the state and answer later
  questions over the same input from it.

What a job may do:: Compute, and call the job effects on the files its
input holds: `file.read!(range)`, `file.contents!()` and
`file.contents_utf8!()` read; `Files.build!({ name, mime, start_from })`
opens a builder, and `append!`, `append_file!` and `finish!` write a new
file the answer may hold, which the page can read, digest and save like a
file the user gave it. A builder never outlives its job, and a job may
append at most 256 MiB. A job cannot wait for a timer, an event or the
network, and the window sees nothing of it until it answers. These effects
are only for jobs: page code cannot call them.

The pool:: One worker per core but one, from one to eight. Jobs beyond
that wait their turn; a stopped job's worker is replaced. `ROC_WORKERS=N`
sets the size. In a spec, use `(worker-pool N)` in
xref:apps.adoc#setup[Setup].

== The environment at launch

The app's boot facts are real: the location is `/`; online and visible are
true; `(prefers-color-scheme: dark)` and `light` follow the system setting,
and any other media query is false; the time, a random seed, the user's
preferred languages and the current time zone, with its transitions, are the
system's.

Quitting, or closing the window, cancels every effect in flight and ends the
program; no turn runs after it. A Roc crash or a host error prints the
message, shows it in an alert and exits with status 1. `dbg` prints to
standard error.
