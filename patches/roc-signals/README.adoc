= Engine patches

The engine modules in `platform/` are roc-signals' at the revision
`docs/architecture.adoc` names (the Engine entry of xref:../../docs/architecture.adoc#how-it-fits-together[How it fits together]),
plus the patches below, applied in order. This list is the series: one line
per patch, with its upstream status. Each patch file is a `git diff` against
the files as they stand after the patches before it, with a header saying
what it changes, why, what it measured before and after, and its upstream
status.

`check`'s `engine` stage reverse-applies the series, last patch first, to a
copy of the engine modules and requires the result to match
`tests/engine-modules.sha256`, the pristine roc-signals digests. It also
requires every `*.patch` here to be listed below, in order, and every listed
patch to exist. A module that differs from pristine plus the series fails the
stage.

== The series

. `0001-mount-handler-function.patch`: mount an event listener in a function of its own, so the turn reaches `mount_attr` unshared and mounting is linear in attributes (box grid at 4,900 cells: 1,479 ms to 25 ms). Upstream: not yet sent.
. `0002-mount-static-nodes-in-functions.patch`: mount elements, comments and texts in functions of their own, so a block's child lists stay unshared and mounting is linear in sites (grid bench, 10,000 cells: 2,360 ms to 74 ms after 0001). Upstream: not yet sent.
. `0003-call-sites-owning-their-captures.patch`: call a site's function outside tail position, and give `Inst` a variant that is never built, so an erased site call owns its captures and rebuilding a block no longer copies its child list; a turn no longer grows with the fan-out of the blocks on its path (grid bench, hover engine p50: 2.5 ms to 0.1 ms at 10,000 cells, 0.1 ms at 14,400). Upstream: not yet sent.
. `0004-write-a-table-in-place.patch`: take a table apart with `match` (in `TableCore.write` and `Engine.inner`), record a written key without `Dict.update`, and hand the modifier the lens's only reference, so a table write is in place (3 rows written, no view: 31 ms to 0.0 ms at a million rows) and building a table with `Table.insert` in a loop is linear (mount engine time: 53 s to 0.15 s at 100,000 rows). Upstream: not yet sent.
. `0005-take-the-root-answer-apart-with-a-match.patch`: take the answer of the root's call apart with `match` in `turn`, so the root's pass owns its block and a `table_view` below it updates its columns in place (3 rows written under a view of every row: 45 ms to 0.1 ms at a million rows after 0004). Upstream: not yet sent.
. `0007-count-table-view-rows.patch`: `table_view_counted`, a `table_view` that sets an attribute of its parent to the number of rows its query keeps, so `Ui.table_list` can draw a small window and size the table for every row (bench/rows, a million rows: mount engine 2,130 ms to 211 ms, apply 1,120 ms to 8 ms, peak RSS 1.57 GB to 366 MB, all from windowing it enables). Upstream: not yet sent.

0001–0005 work around compiler behaviour rather than engine bugs; the
compiler side is in xref:../roc-compiler/README.adoc[patches/roc-compiler].
0007 adds to the engine's API.

== Making a patch

. Change the engine module in `platform/`. Keep the engine's style and run
  `roc fmt --check` on it; never reformat it.
. Write the diff against the files before the change, with `a/` and `b/`
  prefixes (`git diff platform/Core.roc` while the earlier patches are
  committed), and put the header above it, ending with a line `---`.
. Add the patch to the list above, with `Upstream: not yet sent`.

To take a newer engine, copy the modules from one roc-signals commit, drop
the patches that landed upstream (and any that no longer apply), re-make the
rest against the new files, and update `tests/engine-modules.sha256` and the
revision in `docs/architecture.adoc` in the same commit.

When a patch is sent upstream, replace `not yet sent` with the pull
request's link, in this list and in the patch's header.
